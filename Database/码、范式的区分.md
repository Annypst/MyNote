

在《数据库系统概论》（第六版）中，关于“码”的学术定义层层递进，一共有五个最核心的概念。我们用一张“公司员工表”作为背景，把它们一个个揪出来分清楚：

假设员工表有这些属性：`员工号`、`身份证号`、`姓名`、`部门号`、`邮箱`。

### 1. 超码（Super Key）🚀

- **学术定义**：在关系中能**唯一标识**元组（一行数据）的属性集。
- **通俗理解**：只要这个组合能让你精准定位到某一个人，哪怕里面包含了解题不需要的“废话属性”，它也是超码。
- **例子**：`（员工号）`可以唯一标识一个人；而`（员工号，姓名）`也可以唯一标识一个人。所以这两个都是超码。

### 2. 候选码（Candidate Key）🏅

- **学术定义**：**最小的超码**。也就是说，它能唯一标识元组，且**不含有多余的属性**（具有不可约性）。
- **通俗理解**：精简到极致的超码，拿掉任何一个属性，它就无法唯一标识一个人了。
- **例子**：在这张表里，`（员工号）`是候选码，`（身份证号）`也是候选码。但`（员工号，姓名）`就**不是**候选码，因为拿掉`姓名`后，剩下的`员工号`依然能决定所有人，说明`姓名`是多余的。

### 3. 主码（Primary Key）👑

- **学术定义**：用户选作唯一标识元组的**一个**候选码。
- **通俗理解**：候选码可能有好几个（比如员工号和身份证号都能当代表），但数据库设计者最后挑中的那**一个**“正宫”就是主码。
- **例子**：我们选定`员工号`作为这张表的主码。

### 4. 全码（All-Key）🌐

- **学术定义**：关系模型的所有属性组成了这个关系的候选码。
- **通俗理解**：极特殊的情况下，表里没有任何单一属性或部分属性组合能搞定唯一性，必须把**所有列加在一起**才能认出这一行。

### 5. 外码（Foreign Key）🔑

- **学术定义**：一个关系中的某个属性组，它不是这个关系的码，但它是**另一个关系的码**。
- **通俗理解**：派驻到别的表里的“外交官”，用来把两张表死死连在一起。
- **例子**：员工表里的`部门号`。它在员工表里不能唯一标识员工，但它在“部门表”里是主码。

为了测试我们是不是真的分清了，咱们来做一个快速的临考小测验：

> **小思考**：假设有一张“选课表”，属性有：`（学号，课程号，成绩）`。
>
> 一个学生可以选多门课，一门课可以被多个学生选。
>
> 请问：在这张表里，**候选码**应该是什么？（提示：想一想必须拿到哪些属性，才能唯一确定一条成绩记录？）🤔





太棒了！反应非常迅速，而且完全正确！👏👏

在“选课表”`（学号，课程号，成绩）`中，**候选码确实就是`（学号，课程号）`这个组合**。

因为只知道`学号`，我们无法确定是哪门课的成绩；只知道`课程号`，也无法确定是谁的成绩。必须把两者结合起来，才能唯一确定一条成绩记录。这也是我们前面提到的**复合主码**。

既然“键”的概念我们已经理清了，那我们现在正式进入考前最硬核的关卡——**第六章 关系数据理论（关系数据库范式）**。

在期末考试中，范式（Normal Form, NF）通常会作为大题出现，要求你“判断给定的关系最高满足第几范式，并进行规范化分解”**。书上的定义很学术，但核心逻辑其实就是层层递进的**消缺过程。

为了让你在做题时思路清晰，我们先来明确这四个最常考的范式到底在“消除”什么问题：

| **范式级别** | **核心要求（通俗理解）**                                  | **消除的硬伤**                                               |
| ------------ | --------------------------------------------------------- | ------------------------------------------------------------ |
| **1NF** ⭕    | 属性必须是不可再分的**原子项**。                          | 属性中包含复合信息（比如把“地址”写成“省+市+区”在一个格子里）。 |
| **2NF** 🥈    | 在 1NF 基础上，消除了**非主属性对码的部分函数依赖**。     | 拖家带口。非主属性只依赖于复合主码的一部分（比如刚才的选课表里如果加上“学生姓名”，姓名只依赖学号，这就是部分依赖）。 |
| **3NF** 🥉    | 在 2NF 基础上，消除了**非主属性对码的传递函数依赖**。     | 隔山打牛。A 决定 B，B 决定 C，导致 A 间接决定 C（比如：学号 $\rightarrow$ 学院 $\rightarrow$ 学院院长）。 |
| **BCNF** 👑   | 在 3NF 基础上，消除了**主属性对码的部分或传递函数依赖**。 | 连“主打星”（主属性）自己内部也存在不干净的依赖关系。         |

通常，书上的关系数据库都是默认满足 1NF 的，所以考试的重灾区是从 **2NF** 开始。

既然你已经把这几个范式的本质摸透了，我们先用最严谨、最适合临考默诵的学术逻辑，把 **1NF 到 BCNF 的判定流水线** 做一个系统总结。

在考场上拿到一道范式判定大题，你的标准解题步骤应当如下：

## 📐 关系数据库范式（1NF ~ BCNF）判定流水线

### 第一步：基础准备（磨刀不误砍柴工）

在判断任何范式之前，必须先写出两样东西：

1. 题目给出的所有**函数依赖（$X \rightarrow Y$）**。
2. 算出关系模式的**候选码**（如果存在多组，必须全部列出）。
3. 划分属性：包含在任何一个候选码中的属性叫**主属性**；其余的叫**非主属性**。

### 第二步：层层过滤判定

```
  [ 关系模式 R ]
        │
        ▼
 ┌──────────────┐
 │   第一范式   │ ──► 【判定】每个属性都是不可再分的原子项。（期末题默认满足）
 │    (1NF)     │
 └──────┬───────┘
        │
        ▼
 ┌──────────────┐
 │   第二范式   │ ──► 【判定】看有没有“非主属性”对候选码的【部分函数依赖】。
 │    (2NF)     │           (即：非主属性的左边，是不是只占了复合候选码的一部分？)
 └──────┬───────┘           ❌ 有部分依赖 ➔ 停在 1NF
        │                   ✓ 无部分依赖（或候选码全是单属性）➔ 进入 2NF
        ▼
 ┌──────────────┐
 │   第三范式   │ ──► 【判定】看有没有“非主属性”对候选码的【传递函数依赖】。
 │    (3NF)     │           (即：是否存在 候选码 ➔ 属性A ➔ 非主属性B？)
 └──────┬───────┘           ❌ 有传递依赖 ➔ 停在 2NF
        │                   ✓ 无传递依赖 ➔ 进入 3NF
        ▼
 ┌──────────────┐
 │   BC范式     │ ──► 【判定】对【所有】函数依赖 X ➔ Y，检验其左边 X。
 │   (BCNF)     │           (不管是主属性还是非主属性，只要在左边充当决定因素)
 └──────────────┘           ❌ 存在某个 X 不是整个关系的候选码 ➔ 停在 3NF
                            ✓ 所有 X 都是候选码 ➔ 完美达到 BCNF
```

## 🥊 第一拳：判定 2NF（只看有无“单根零件”毒素）

你要检查整个系统有没有发生“部分函数依赖”。

- **你的扫描雷达**：盯着依赖集里所有**右边是非主属性**的式子看。
- **你眼里的“毒素结构”**：只有当左边是**纯净的 $A$ 单个**，或者**纯净的 $P$ 单个**去指向非主属性时，才叫部分依赖（中毒了）。
- **对待杂质的判词**：像 $AB \rightarrow C$ 这种左边长了杂质的，它在学术上叫“完全函数依赖”（因为少了一个字母它就推不出 $C$ 了，它必须绑在一起，所以没有偷懒部分依赖）。**因此，它在 2NF 的审判庭里是完全无罪的，直接不管它！**

> 🎯 **本题宣判**：整个依赖集里没有任何一条是 $A \rightarrow \text{非主}$ 或者 $P \rightarrow \text{非主}$。**全身排毒成功，100% 稳过 2NF！**

## 🥊 第二拳：判定 3NF（只看有无“狗尾续貂”传递）

既然 2NF 已经稳拿了，那这个 $AB \rightarrow C$ 的杂质，在接下来的 3NF 审判里会扮演什么角色呢？**它会在传递依赖里露出马脚！**

- **你的扫描雷达**：看那些左边是杂质、右边也是非主属性的式子。
- **真实逻辑链条演练**：
  1. 我们的至高神（码） $(AP)$ 可以通过一条干净的依赖推导出 $C$ ➡️ **$(AP) \rightarrow C$**。
  2. 这时候，那个带杂质的 $AB \rightarrow C$ 根本不用看。但你往后看，题目里是不是有：**$C \rightarrow D$**，然后 **$D \rightarrow B$**？
  3. 发现了没有！非主属性 $C$、 $D$、 $B$ 之间在**手拉手玩多米诺骨牌**！
  4. 最终形成了：**码 $(AP) \rightarrow \text{非主属性 } C \rightarrow \text{非主属性 } D \rightarrow \text{非主属性 } B$**。

> 🎯 **本题宣判**：这就是最标准的**传递函数依赖**（狗尾续貂）。因为发生了非主属性之间的连环传递，3NF 宣告当场流产！**所以它最高只能停留在 2NF。**

## 🏁 战友对齐：你的考场大局观已经无懈可击

你刚才说的那句“*如果有这种其他杂质就不管他了*”，在数据库规范化理论里是一个极其高明的**过滤策略**。

过几天坐在太原理工软件学院的考场上，拿到这 10 分大题，你就用这个心态去降维打击：

1. **L-R 矩阵锁死唯一候选码 $(AP)$。**
2. **两手一摊：左边没有纯 $A$ 或纯 $P$ 指向非主属性 ➡️ 直接宣布满足 2NF。**
3. **顺藤摸瓜：看到 $C \rightarrow D \rightarrow B$ 连环手拉手 ➡️ 宣告违反 3NF，最高属于 2NF。**
