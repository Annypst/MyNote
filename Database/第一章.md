

# 📘 数据库系统概论（第六版）期末复习笔记 —— 第一章 绪论

## 💾 一、 数据管理技术的演变史

数据管理技术随硬件和需求的发展，经历了三个标志性阶段：

| **发展阶段**                             | **主体特点 🛠️**                                               | **致命痛点 ⚠️**                                               |
| ---------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **人工管理阶段** (50年代中期前)          | • 计算机主要用于科学计算 • 数据不保存，不独立 • 数据面向特定程序 | • 程序员需要手动编排数据存储逻辑 • 重复录入，负担极重        |
| **文件系统阶段** (50年代后期-60年代中期) | • 磁盘等存储设备出现 • 数据可以文件形式**长期保存** • 由操作系统统一管理 | • **数据冗余度大**：易导致数据不一致 • **数据独立性差**：文件结构改了，程序就得重写 |
| **数据库系统阶段** (60年代后期以来)      | • 统一管理，**高度共享** • 具有极高的**数据独立性**          | • 相比文件系统，系统开发和维护成本更高                       |

## 🧱 二、 数据模型的三要素与分类

### 1. 数据模型的三要素 📐

任何一种数据模型都必须具备以下三个核心部件：

- **数据结构**（静态特征）🟥：研究“**有什么**”。描述数据库的组成对象以及对象之间的联系（如：有哪些表、哪些字段）。
- **数据操作**（动态特征）🔄：研究“**怎么做**”。对数据库中各种对象的实例允许执行的操作集合（如：SELECT、INSERT、UPDATE、DELETE）。
- **数据的完整性约束**（限制条件）🛡️：研究“**必须满足什么规则**”。一组完整性规则的集合，用以限定符合现实世界的合法数据（如：主键不能重复、年龄不能为负数）。

### 2. 数据模型的分类 🎨

- **概念模型**（面向现实世界）：数据库设计的第一步，纯粹从人的视角抽象业务逻辑，不依赖具体软件。典型代表：**E-R 图（实体-联系模型）**。
- **结构模型**（面向计算机世界）：把概念模型翻译成数据库软件能听懂的语言。
  - *层次模型* 🌲：用树状结构表达（规定：有且仅有一个节点无双亲，其他节点有且仅有一个双亲）。**缺点：表达多对多极其冗余**。
  - *网状模型* 🕸️：用网状结构表达（允许节点无双亲或有多个双亲）。**缺点：结构复杂，查询时需指定存取路径**。
  - *关系模型* 📊：用**二维表**表达。表与表之间的联系靠**数据本身的值**维持，不需要物理指针。**目前最主流的模型**。

## 🗺️ 三、 数据库系统的三级模式两级映像

### 1. 三级模式结构 🏢

- **外模式（External Schema）/ 用户级** 👁️：用户或程序员看到的局部逻辑结构和特征，通常表现为视图（View）或定制接口。
- **模式（Schema）/ 概念级** 📊：所有用户的公共数据视图，数据库中全体数据的全局逻辑结构和特征，核心体现为**表结构（Table）与约束**。
- **内模式（Internal Schema）/ 物理级** 💾：数据在系统内部的表示方式和物理存储结构（如：是否加**索引**、存储是否加密或聚簇）。

### 2. 两级映像与数据独立性 🔗

通过在三层之间架设两座“桥梁”，实现了“隔山打牛”的数据独立性：

```
外模式 (视图) 
    │
    ├── 1. 外模式/模式映像 ── 保证 [逻辑独立性]：模式(表结构)改了，软件代码不用重写。
    │
模式 (总表结构) 
    │
    ├── 2. 模式/内模式映像 ── 保证 [物理独立性]：内模式(硬盘存储/索引)改了，表结构和软件不用动。
    │
内模式 (硬盘物理存储)
```

### 3. 数据库管理员（DBA）的职责 👑

作为数据库的“最高大管家”，主要负责：定义三级模式、决定存储结构和存取策略、安全性与完整性控制、故障恢复与数据备份。





🏢 什么是“模式（Schema）”？

在数据库的世界里，**“模式（Schema）”\**其实就是数据库的\**“设计图纸”\**或者\**“骨架”**。

我们可以用盖房子来做一个非常形象的类比：

- **模式（Schema）** 📜：就是房子的**设计图纸**。图纸上画着这里是客厅、那里是卧室、墙有多厚。图纸本身是没有砖瓦和居民的，它只规定了**结构和规则**。在数据库里，模式定义了有哪些表、每个表有哪些列、这些列是什么类型（数字还是文本）。
- **实例（Instance）** 🛋️：就是按照图纸真正盖出来的、里面住了人的**房子**。房子里具体的家具和居民，就是数据库里**实际存储的数据**。这些数据是会随着时间不断变化的（比如今天搬进来一个人，明天买了一个沙发）。

> 💡 **学术铁律**：
>
> - **模式**是**相对稳定的**（设计图纸轻易不会改）。
> - **实例**是**动态变化的**（表里的数据随时在增删改）。

## 📐 核心考点：三级模式结构

高教社第六版教材中，最核心的理论就是数据库的“三级模式结构”。数据库之所以要设计成三层，就是为了实现“隔山打牛”的效果，让用户、程序员和底层硬盘之间互不干扰。

我们从上到下（从用户看到的东西，到硬盘里存的东西）来拆解这三层：

```
   ┌────────────────────────────────────────┐
   │  外模式 (External Schema) / 用户级      │  ➔ 程序员和用户看到的局部视图
   └───────────────────┬────────────────────┘
                       ▼
   ┌────────────────────────────────────────┐
   │    模式 (Schema) / 概念级               │  ➔ 整个数据库的全局逻辑结构
   └───────────────────┬────────────────────┘
                       ▼
   ┌────────────────────────────────────────┐
   │  内模式 (Internal Schema) / 物理级      │  ➔ 数据在硬盘上怎么存的物理结构
   └────────────────────────────────────────┘
```
