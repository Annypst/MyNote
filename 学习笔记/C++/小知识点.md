在 C++ 中，`nullptr` 只有一个含义：**“我是一个指针，但我现在谁也不指向。”**

我们在大一学 C 语言时，如果想表达一个指针是空的，通常写成：

```
int* p = NULL; // C 语言写法
```

这里的 `NULL` 在底层其实就是数字 **`0`**（编译器会用 `#define NULL 0` 来宏定义）。 但是，把“指针为空”等同于“数字 0”会导致很多奇怪的语义混乱（比如编译器会分不清你到底传入的是数字 `0` 还是一个空指针）。

为了解决这个不严谨的问题，现代 C++ 专门发明了一个全新的关键字：**`nullptr`**。

- 它代表**且仅代表**“空指针”，不能被当成数字 `0` 来看待。

- 只要你声明一个指针，但一时间不知道让它指向哪，请务必把它初始化为 `nullptr`

  ```
  int* p = nullptr; // 安全，大家都知道这是一个空指针
  ```

### 当 `const` 遇到“指针”（C++ 面试超高频考点）

指针变量有两个部分：**指针变量本身（存门牌号的房子）** 和 **指针指向的数据（门牌号对应的那个房子里的内容）**。 这就导致 `const` 在修饰指针时，由于放的位置不同，会产生两种截然不同的限制（这也是 C++ 程序员必须抠得很细的地方）：

#### 情况 A：`const` 在星号 `*` 左边 —— 限制“内容”不能改（常量指针）

C++

```
int a = 10;
int c = 30;

// const 在 * 的左边：说明指针指向的【数据】是常量
const int* p = &a; 

*p = 20; // 报错！因为 const 在左边，限制了不能通过 p 去修改 a 的值（数据被锁死）
p = &c;  // 成功！p 本身（存哪个门牌号）可以改，它改去指向 c 了。
```

#### 情况 B：`const` 在星号 `*` 右边 —— 限制“指向”不能改（指针常量）

C++

```
int a = 10;
int c = 30;

// const 在 * 的右边：说明指针【本身】是常量
int* const p = &a; 

*p = 20; // 成功！a 的值被顺利改成了 20（数据没锁死）
p = &c;  // 报错！因为 const 在右边，锁死了指针本身的指向，p 永远只能指向 a，不能“变心”！
```

> **💡 记忆口诀**： 倒过来读！
>
> - `const int* p` -> `const` 修饰 `*p`（数据），所以数据不能改。
> - `int* const p` -> `const` 修饰 `p`（指针），所以指向不能改。

而在 C++ 中，我们使用 **冒号 `:`** 来表示继承。它就像是一条纽带，把子类和父类连接在一起：

C++

```
class NvidiaH100 : public GPU { ... }; // C++ 写法
```

## 🛠️ 重写（Override）的语法保障

在子类中重写父类的虚函数时，C++11 引入了一个非常好用的安全卫士关键字：**`override`**。

C++

```
class NvidiaH100 : public VirtualGPU {
public:
    // override 关键字显式告诉编译器：我这是在重写父类的虚函数！
    void runTask() override { 
        std::cout << "【H100】全速训练..." << std::endl;
    }
};
```

### 为什么强烈建议写 `override`？

在 C++ 里，函数重写要求**函数签名（函数名、形参列表、`const` 属性等）必须一模一样**。 如果你一不小心把形参写错了，比如父类是 `virtual void test(int a)`，子类不小心写成了 `void test(double a)`：

- **不加 `override`**：编译器不会报错，它会以为你只是在子类里定义了一个全新的**同名重载函数**。多态会直接失效，运行时莫名其妙不调用子类，调试极难排查。
- **加上 `override`**：编译器在编译时会去父类对比。一对比发现签名不一致，立刻报错弹窗：“你在声明重写，但我没在父类里找到这个虚函数！”在编译期就帮你排了雷。
