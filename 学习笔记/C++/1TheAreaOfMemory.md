#  C++ 内存四区

2026/7/15

在 C++ 中，程序运行后的整个物理内存被划分为四个功能不同的区域。**身为 C++ 程序员，你写的每一行代码、声明的每一个变量，都必须明确知道它落在哪一个区。**

### 一、 代码区 (Code Area)

- **存放内容**：存放 CPU 执行的**二进制机器指令**（即你写的全部代码编译后的产物）。
- **生命周期**：程序运行前即生成，直到**程序结束**才由操作系统释放。
- **核心特点**：
  - **只读 (Read-Only)**：防止程序在运行过程中意外或者被恶意修改其指令。
  - **共享 (Shared)**：对于频繁执行的程序（比如同时打开两个相同的软件），内存中只需要有一份代码即可，节省内存。

### 二、 全局/静态区 (Global / Static Area)

- **存放内容**：存放**全局变量**（写在函数外面的变量）和**静态变量**（用 `static` 关键字修饰的变量），以及**常量**（如字符串常量 `"Hello"`）。
- **生命周期**：在程序编译时就分配好了内存，随着程序的启动而存在，直到**程序结束**由系统释放。
- **核心特点**：
  - 该区域的数据在程序运行期间**一直有效**，可以跨函数共享。
  - 在 C++ 中，它通常细分为全局区（存放初始化的和未初始化的全局/静态变量）和常量区（存放只读常量）。

### 三、 栈区 (Stack Area)

- **存放内容**：存放**函数的局部变量**、**函数参数值**。
- **生命周期**：由**编译器自动分配和释放**。进入变量所在的作用域（如大括号 `{}`）时出生，**离开作用域（函数结束）时瞬间被系统自动销毁**。
- **核心特点**：
  - **速度极快**：硬件级别有特殊的寄存器和指令集支持。
  - **空间较小**：通常只有几 MB（不同操作系统限制不同），分配过多会导致**栈溢出 (Stack Overflow)**。
  - **最大隐患**：千万不要返回栈区局部变量的地址（指针），会导致悬空指针崩溃！

### 四、 堆区 (Heap Area)

- **存放内容**：由**程序员手动开辟和释放**的内存（在 C++ 中通过 `new` 关键字创建的对象）。
- **生命周期**：完全由程序员掌控。从 `new` 那一刻出生，直到程序员调用 **`delete`** 那一刻消亡。如果不主动 delete，只有等程序彻底关闭后才被操作系统强行回收。
- **核心特点**：
  - **空间极大**：可以吃满你电脑的物理内存条。
  - **自由度高**：数据的生命周期不受大括号限制，可以跨函数、跨线程传递。
  - **最大隐患**：如果用完忘记 `delete`，会导致**内存泄漏 (Memory Leak)**；如果重复 `delete` 或者提前 `delete` 后继续使用，会导致程序闪退。

## 四区对比图

| **内存分区**    | **分配者** | **释放者**        | **空间大小**            | **特点**                               |
| --------------- | ---------- | ----------------- | ----------------------- | -------------------------------------- |
| **代码区**      | 操作系统   | 操作系统          | 取决于代码量            | 只读、共享、装二进制指令               |
| **全局/静态区** | 编译器     | 操作系统          | 较小                    | 程序运行期间一直活着，装全局/静态/常量 |
| **栈区**        | 编译器     | 编译器 (自动)     | 极小 (几MB)             | 速度最快，生命周期短，出大括号必死     |
| **堆区**        | **程序员** | **程序员 (手动)** | **极大 (取决于内存条)** | 最具灵活性，C++ 核心控战场，生死自负   |

###  为什么 C++ 不继续只用 `malloc`，而是发明了 `new`？

这也是大厂面试非常高频的一个考点，它直接关系到我们后面要学的**面向对象（OOP）**：

1. **`malloc` 只是单纯的“分肉”机器**：它只负责去内存条上割下指定大小的字节空间（比如 4 字节），它**根本不知道、也不关心这块内存里装的是什么对象**。
2. **`new` 是“智能装配线”**：当你在 C++ 里 `new` 一个类的对象时，它不仅会在堆区开辟内存，还会**自动调用这个类的“构造函数”**，帮你把对象初始化好。同理，`delete` 时也会自动调用“析构函数”来清理资源。而 `malloc` 和 `free` 绝对不会触发构造和析构。
