# IO方式、中断过程

## 🗺️ 第一部分：四大高频 I/O 方式大盘点

外部设备（如键盘、硬盘）和主存之间传数据，历史上演进出了四种流派。考试最喜欢考它们“对 CPU 的打扰程度”。

### 1. 程序查询方式（Polling / 轮询）—— “夺命连环催”的老板

- **硬件本质**：外设和 CPU 之间没有任何通知信号线。
- **物理过程**：CPU 发出启动外设命令后，就**卡在一条死循环代码里**，不停地去读外设的状态寄存器：“你好了没？”“你好了没？”“你好了没？”……直到外设把数据准备好，CPU 才能把数据读走。
- **致命缺点**：在设备准备数据的这段漫长时间里，**CPU 处于 100% 的空转状态**，什么别的活都干不了，外设和 CPU 完全串行工作。

### 2. 程序中断方式（Interrupt）—— “随叫随到”的秘书

- **硬件本质**：引入了一条硬连线——**中断请求线（INTR）**。
- **物理过程**：CPU 下达命令后，转头去运行别的常规程序。外设自己默默准备数据，准备好一个字（Word）之后，啪的一下踩一脚电平，通过 INTR 给 CPU 发中断。CPU 收到通知后，过来**亲自搬运这个字**，搬完后继续回去做原来的事。
- **核心特点**：CPU 和外设实现了**部分的并行工作**。但缺点是“按字传输”，如果是大块数据，CPU 会被频繁的中断活活累死。

### 3. DMA 方式（Direct Memory Access）—— “独当一面”的主管

- **硬件本质**：在总线上架设了一个专用的硬件——**DMA 控制器（DMAC）**。
- **物理过程**：CPU 彻底解放双手，直接对 DMAC 下达总动员令：“去，把外设上这 4KB 的数据直接给我搬到主存 XXX 地址。”随后，DMAC 强行接管系统总线，**直接在主存和外设之间连线搬运**。
- **核心特点**：实现了“按数据块传输”。在传输过程中**完全不需要 CPU 参与**，只有在整块数据全部搬完后，DMAC 才发一次中断通知 CPU 验收成果。

### 4. 通通方式（Channel）—— “全权代理”的 CEO

- **硬件本质**：它是一台**专门管理 I/O 的极其精简的小型处理器**，有自己的指令集和通道程序。
- **物理过程**：CPU 只要在主存里写好一个“总合同”（通道程序），然后告诉通道“你去执行吧”。通道自己去读指令、控总线、管理成百上千个设备，做完之后向 CPU 汇报。
- **核心特点**：CPU 只需要在“开头”和“结尾”打个照面，剩下的**全自动化管理**，是大型主机里最顶级的 I/O 架构。

## 🔄 第二部分：中断处理的“全生命周期”流程

考试如果出大题，最喜欢考“一个中断从发生到结束，硬件和软件分别干了什么，顺序是什么”。我们把这个过程拆解为**纯硬件干的“隐指令”三部曲**和**纯软件干的“服务程序”四部曲**。

### 🛠️ 阶段一：硬件自动冲锋（中断隐指令周期）

当一条指令执行到末尾时，CPU 硬件检测到有外设中断请求，**硬件电路**会在不需要任何软件代码干预的情况下，自动完成以下三步：

1. **关中断**：瞬间切断 INTR 的响应，把大门关死，防止在保存现场时被其他中断冲刷。
2. **保护断点**：把当前的 PC（下一条指令的地址）压入堆栈或者专门的硬件寄存器（如寄存器 EPC）。
3. **引出中断服务程序**：硬件通过排队判优，把对应的**向量地址**（中断服务程序的入口地址）送入 PC，引导 CPU 强行跳转。

### 💻 阶段二：软件接力干活（中断服务程序 ISR 内部）

CPU 的 PC 被强行修改后，开始执行操作系统内核的中断软件代码。代码会依次执行这四个动作：

1. **保护现场**：硬件只帮我们存了 PC，但通用寄存器（如 ACC、X）里的数据还在。软件必须赶紧执行一堆 `PUSH` 指令，把这些寄存器的数值压进堆栈存起来。
2. **开中断（可选）**：如果系统允许**中断嵌套**（也就是说允许更高级的中断来插队），这时候现场已经存好了，软件会执行一条开中断指令，允许新中断进来。
3. **执行中断主体（干正事）**：这是最核心的业务逻辑。如果是键盘中断，就去读扫描码；如果是打印机中断，就往外送数据。
4. **恢复现场并退出**：正事干完后，软件执行一堆 `POP` 指令把寄存器的原值拿回来。最后，执行一条特殊的**中断返回指令（如 `IRET`）**。这条指令在硬件上会**自动开中断**，并且把堆栈里的**断点地址弹回 PC**，CPU 瞬间穿越回被中断前的那个历史瞬间，继续若无其事地运行主程序。

## 🧭 核心考点一：中断 vs DMA，到底谁在“干活”，谁在“报告”？（对应第2题）

第 2 题的表述**完全说反了**。这是考研和期末考试最喜欢考的“张冠李戴”陷阱。

### 1. 程序中断方式：中断是为了“进行数据传输”

- **物理场景**：CPU 正在愉快地运行主程序，I/O 设备（比如键盘输入或硬盘读一个字）准备好了一个字（Word）的数据，就会向 CPU 发出中断请求。
- **谁来传数据**：CPU 收到请求后，**必须停下手里所有的工作**，切换到中断服务程序（ISR），伸出双手亲自把这个字从 I/O 接口的寄存器里读出来，再存进主存里。
- **结论**：在中断方式下，**每一次中断请求，都是为了让 CPU 过来“亲自动手搬运这一个字的数据”**。

### 2. DMA 方式：中断是为了“报告传输结束”

- **物理场景**：要传输的数据量太大了（比如几百个 KB 的数据块），如果每传一个字都要中断一次 CPU，CPU 就会被活活累死。于是硬件上派出了一个专门的无脑苦力——**DMA 控制器（DMAC）**。
- **谁来传数据**：CPU 告诉 DMAC “你把这块数据直接从设备挪到主存里，我不管了”。然后 DMAC 直接接管总线，**不需要 CPU 的任何干预**，自己默默地把成百上千个字全部搬完。
- **结论**：当整个数据块彻底搬完后，DMAC 才会向 CPU 发出一个中断请求，意思是：“报告老大，那一大块数据我全搬完了，你现在可以放心用了。”所以，**DMA 的中断，纯粹是为了报告传输结束**。

> 💡 **一句话秒杀**：
>
> 中断方式是“每搬一个字就打扰一次 CPU”；DMA 方式是“DMAC 自己把一整块搬完，最后只打扰一次 CPU 汇报成果”。

## 🚨 核心考点二：中断响应周期，硬件自动完成的“三部曲”（对应第5题）

第 5 题错在一个极其致命的字——**“开”中断**。在中断响应周期，硬件必须无条件执行“关”中断！

当 CPU 在一条指令执行结束时检测到有中断请求，并且满足响应条件，就会自动进入一个由纯硬件电路（中断隐指令）执行的“中断响应周期”。在这个周期里，硬件会雷打不动地完成以下三件事：

1. **关中断（Disable Interrupts）❌ 题目写成了“开中断”**
   - **为什么必须关？** CPU 正准备去保存当前的现场（断点），这就好比你在银行往保险箱里存重要传家宝。在你的传家宝完全锁进保险箱之前，**必须先把大门关死**！否则如果这时候又来一个级别更高的中断，直接把你的 PC 指针给冲刷掉了，你就再也找不到回家的路了。
2. **保护断点（Save Breakpoint）**
   - 把当前程序计数器 PC 的值（即下一条本该执行的指令地址）强制压入堆栈，或者存到特定的寄存器里。
3. **发中断响应信号并形成向量地址（Vector Address）**
   - 硬件产生中断响应信号（INTACK），并由硬件电路（比如排队判优电路、向量地址形成部件）自动生成对应的**向量地址**（即中断服务程序的入口地址映射），直接送入 PC，引导 CPU 跳过去执行软件代码。

### 📅 那什么时候才会“开中断”？

“开中断”是一个**软件动作**。当硬件完成了上述三步，CPU 安全地跳进了中断服务程序（ISR）内部，并且把那些不能被冲刷的关键寄存器（如通用寄存器、程序状态字）都用软件代码压栈保护好之后，如果系统允许更高级的中断嵌套（多重中断），软件才会执行一条 `STI`（开中断）指令，把大门重新打开。
