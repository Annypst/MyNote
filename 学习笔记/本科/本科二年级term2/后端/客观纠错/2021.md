# 🎯 第一部分：错题与高频考点速查清单

### 1. 数据交互的“两个管道”

- 

  **`request.getParameter("键")`**：单向被动接收流。用于获取前端（表单、URL 拼接）传过来的底层**字符串数据** 。  

- 

  **`request.setAttribute("键", 值)`**：内部主动存储口袋。用于在服务器内部（如 Servlet 存入数据后转发给 JSP）存储**任意 Java 对象** 。  

### 2. 会话管理的底层硬伤

- 

  **`JSESSIONID`**：Session 机制的灵魂纽带。服务器在内存中创建 Session 后，必须通过名为 `JSESSIONID` 的 Cookie 将其唯一会话标识发给浏览器 。  

- 

  **Cookie 的厂商铁限制**：浏览器存储 Cookie 不是无限的，单域名下通常限制在 20~50 个，总大小不超过 4KB，绝对不存在“任意多、任意长” 。  

### 3. 应用域（Application Scope）的边界

- 

  `application`（即 `ServletContext`）的作用域是**单应用全局**。这意味着它的数据只能在**当前这一个 Web 项目/应用**内部被所有 Servlet/JSP 共享，不同 Web 项目之间存在物理隔离，无法共享 。  

### 4. 包含语法的“制服绑定”

- 

  **动态包含**：必须写成 **`<jsp:include page="URL" />`**（冒号标签配 `page` 属性） 。  

- 

  **静态包含**：必须写成 **`<%@include file="URL" %>`**（百分号指令配 `file` 属性） 。  

### 5. `web.xml` 过滤器的配置血缘

- 注册过滤器类使用 `<filter>` 标签；配置其拦截规则使用 `<filter-mapping>` ；而在映射标签内，真正写入具体拦截虚拟路径的子标签是 **`<url-pattern>`** 。  

### 6. DBUtils 单条记录映射公式

- 若 SQL 语句中带有问号占位符（如 `WHERE id=?`）且要求查询单条记录，必须使用 **`BeanHandler`**（将单行映射为单个 Java 对象）并传入具体的参数值数组或可变参数 。  

# 🎯 第二部分：错题干扰选项全盘学术清算

🛠️ 选择题第 8 题：数据存放动作辨析   

> **原题**：如果想要将页面传递来的用户名 username 为张三的数据存放在 Request 对象中，以下哪种方式可以实现   

- **A: `String username=request.getParameter("张三");`**

  - 

    **学术纠偏**：彻底错误。该方法是试图去请求域中获取名为“张三”的前端入参 。此时前端传过来的键是 `username`，值是`张三`，这个写法属于键值颠倒且方法用反。  

- **B: `String username=(String) request.getAttribute("张三");`**

  - 

    **学术纠偏**：错误。`getAttribute` 是从 Request 域中**读取/取出**已经存在的属性 ，而题干的要求是“存放在 Request 对象中”。  

- 

  **C: `request.setAttribute("username", "张三");`**   

  - 

    **标准答案**：**正确**。通过 `setAttribute(键, 值)` 将数据塞进 Request 域中 。  

- **D: `request.removeAttribute("张三");`**

  - 

    **学术纠偏**：错误。这是从 Request 域中彻底**删除/销毁**名为“张三”的属性值 。  

🛠️ 选择题第 16 题：Cookie 与 Session 特性辨析   

> **原题**：下列关于 Cookie 和 Session的描述中，错误的是   

- 

  **A: Cookie 和 HttpSession 是保存会话相关数据的技术，其中 Cookie 将信息存储在浏览器端是客户端技术，Session 将数据保存在服务器端是服务器端技术**   

  - **学术纠偏**：陈述完全正确。指明了两者在物理存储位置上的本质区别。

- 

  **B: HttpSession 会话对象的默认保持时间可以修改**   

  - 

    **学术纠偏**：陈述完全正确。可以通过调用 `session.setMaxInactiveInterval()` 或在 `web.xml` 里的 `<session-timeout>` 标签进行自定义修改 。  

- 

  **C: HttpSession 默认是基于 Cookie 运作的**   

  - 

    **学术纠偏**：陈述完全正确。Session 依赖 Cookie 在客户端存放 `JSESSIONID` 来识别用户身份 。  

- 

  **D: 浏览器可以接受任意多个 Cookie 信息保存任意长的时间**   

  - 

    **标准答案**：**陈述错误（故本题选 D）** 。触犯了浏览器厂商的硬件级硬限制，数量和存活时间都有天花板。  

🛠️ 选择题第 20 题：JSP 作用域边界辨析   

> **原题**：下面关于 JSP 作用域对象的描述，错误的是   

- 

  **A: request 对象可以得到请求中的参数**   

  - 

    **学术纠偏**：陈述完全正确。可以通过 `request.getParameter()` 顺利拿到请求参数 。  

- 

  **B: session 对象可以保存用户信息**   

  - 

    **学术纠偏**：陈述完全正确。Session 作用域生命周期横跨多次请求，非常适合存放用户的登录态和购物车数据 。  

- 

  **C: application 对象可以被多个应用共享**   

  - 

    **标准答案**：**陈述错误（故本题选 C）** 。`application`（ServletContext）属于单应用全局共享，在不同的 Web 项目之间是无法跨越共享的。  

- 

  **D: 作用域范围从小到大是 request、session、application**   

  - 

    **学术纠偏**：陈述完全正确。层级范围链 request（单次请求） < session（单会话） < application（整个应用运行期）完全成立 。  

🛠️ 选择题第 23 题：动态包含语法辨析   

> **原题**：下面关于动态包含的语法格式，书写正确的是   

- 

  **A: `<jsp:forward file=" relativeURL">`** 与 **B: `<jsp:forward path=" relativeURL" />`**   

  - 

    **学术纠偏**：彻底错误。`<jsp:forward>` 是服务器端**请求转发**标签，不仅功能与题目要求的“包含”相悖，且其标准属性是 `page`，压根没有 `file` 或 `path` 属性 。  

- 

  **C: `<jsp:include page=" relativeURL" />`**   

  - 

    **标准答案**：**正确**。动态包含动作标签，前缀是 `jsp:`，属性必须配 `page` 。  

- 

  **D: `<%@include file=" relativeURL">`**   

  - 

    **学术纠偏**：混淆项。这句语法本身完全合法，但它的真实学术身份是**静态包含指令**（编译时包含），而题干指名道姓要求找**动态包含** 。  

🛠️ 选择题第 26 题：过滤器标签配置辨析   

> **原题**：下列选项中，用于匹配过滤器所拦截的 URL 的元素是   

- 

  **A: `<filter-mapping>`**   

  - 

    **学术纠偏**：范围过大。这是配置过滤器映射关系的**父级大标签**，它内部包含了解析名称和具体规则，其本身不能直接写 URL 。  

- 

  **B: `<url-pattern>`**   

  - 

    **标准答案**：**正确**。专门用于精确指定过滤器要拦截的虚拟路径 URL 规则 。  

- 

  **C: `<filter>`**   

  - 

    **学术纠偏**：张冠李戴。这是用于**注册/声明**过滤器类的父级大标签，里面包裹的是 `<filter-name>` 和 `<filter-class>`，与拦截路径无关 。  

- 

  **D: `<filter-name>`**   

  - 

    **学术纠偏**：错误。这是过滤器的注册别名，用于让 `<filter>` 标签和 `<filter-mapping>` 标签通过名字建立血缘绑定 。  

🛠️ 选择题第 29 题：DBUtils 查询对象传参辨析   

> **原题**：若使用 QueryRunner 类对象 runner 执行 SQL 语句：`String sql = "select * from user where id=?"`，能实现查询指定记录的操作是   

- 

  **A: `User user = (User)runner.query(sql, new BeanListHandler(User.class), new Object[]{id});`**   

  - 

    **学术纠偏**：编译与类型报错。`BeanListHandler` 会将查询结果打包成一个 `List<User>` 集合返回，你无法把一个 List 集合直接强转为单个 `User` 对象 。  

- 

  **B: `User user = (User)runner.query(sql, new BeanHandler(User.class));`**   

  - 

    **学术纠偏**：运行时报错。SQL 语句里带有一个 `?` 占位符，但该选项在调用方法时完全没有传入用来替换问号的 `id` 变量，会抛出参数个数不匹配异常 。  

- 

  **C: `User user = (User)runner.query(sql, new BeanListHandler(User.class), id);`**   

  - 

    **学术纠偏**：同 A 选项错误。使用了 `BeanListHandler`，其返回值是集合类型，强转为单个对象会导致运行时类型转换异常（ClassCastException） 。  

- 

  **D: `User user = (User)runner.query(sql, new BeanHandler(User.class), new Object[]{id});`**   

  - 

    **标准答案**：**正确** 。`BeanHandler` 确保返回单个对象，且后面的数组完美填充了问号占位符 。
