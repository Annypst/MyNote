**问：在发生多次服务器内部请求转发（Forward）时，`requestScope` 里的数据会丢失吗？**

 解答**：**绝对不会。 在 Java Web 规范中，无论在后台连续经历了多少次 `forward` 转发，整个链条中的所有 Servlet/JSP 组件都在共享由客户端浏览器发起的**同一次 HTTP 请求**。Tomcat 在底层会将同一个 `request` 对象像接力棒一样原封不动地向后传递，因此最初存入 `requestScope` 的数据会一路顽强继承，直到最后一个页面完美输出。  只有当中间组件调用了**重定向（Redirect）**时，浏览器才会重新发起第二次全新的请求，此时旧的 `request` 瞬间死亡，数据切断。

**JSP 中包含文件的动作标签 `<jsp:include>` 与指令 `<%@include>` 在语法属性上有何硬性绑定？** 

解答：在 JSP 语法规范中，标签前缀与属性名是严格绑定的，绝对不能张冠李戴：  动态包含（动作标签）：必须写成 `<jsp:include page="URL"/>`（前缀有冒号 `jsp:`，属性必配 `page`）。  静态包含（指令格式）：必须写成 `<%@include file="URL"/>`（前缀带百分号 `<%@`，属性必配 `file`）。  语法排雷：考卷中如果拼出 `<jsp:include file="..."/>` 这种格式，属于严重语法错误，Tomcat 编译时会直接报错。

**问：多级过滤器链（FilterChain）的执行顺序是怎样的？如果某个过滤器故意不写放行代码会发生什么？** 

解答：  正常执行顺序（回形针/回音谷模型）：请求去时按照配置顺序**正序**拦截（Filter 1 ➡️ Filter 2 ➡️ Servlet），响应回时按照配置顺序逆序穿出（Servlet 2 ➡️ Filter 2 ➡️ Filter 1）。核心分水岭是 `chain.doFilter(request, response);` 语句。  缺失放行代码的断流灾难：如果某个 Filter 内部**没有**调用 `chain.doFilter`，该请求将彻底失去向前递交的传送门，后续的 Servlet 或后续的过滤器将被物理屏蔽、根本不会执行。当前 Filter 跑完后，程序会直接带着残局原路退栈返回。

**问：JSP 脚本元素（Scripting Elements）到底包含哪几种？哪些常被拿来混淆？**

* 解答：JSP 规范中严格定义的脚本元素只有以下三种（它们都可以直接嵌套 Java 代码）：
  1. JSP Scriptlets（小脚本） ➡️ 语法：`<% Java代码 %>`。用于编写普通的 Java 业务逻辑、控制流 [cite: 131]。
  2. JSP 表达式（Expression） ➡️ 语法：`<%= Java表达式 %>`。用于在网页上直接输出变量或表达式的值（注意：末尾绝对不能加分号）
  3. JSP 声明标识（Declaration） ➡️ 语法：`<%! 全局变量/方法声明 %>`。用于声明全局变量或定义类的方法 。
* 考场生死线（判断题死穴）：
  * 指令标识（`<%@ page ... %>` 等）和 动作标签（`<jsp:forward>` 等） 绝对不属于脚本元素！如果判断题说“JSP 指令属于脚本元素的一种”，直接打叉。


**问：JSP 隐式对象 `out` 的真实类型是什么？它和 `response.getWriter()` 究竟是什么恩怨关系？**

* 解答：这是太理判断题（如第 5 题）和选择题（如第 11 题）连续重拳出击的底层细节 ：
  1. 真实类型：JSP 的 `out` 对象类型是 `javax.servlet.jsp.JspWriter`，它是一个自带缓冲区的输出流。
  2. 绝对不是一回事：`out` 并不是通过 `response.getWriter()` 获取的 。`response.getWriter()` 获取的是标准 Servlet 的 `PrintWriter`。它们在 Tomcat 底层是两个完全独立、各走各路的缓冲区 [cite: 58-61]。
  3. 谁先输出？（时间差大坑）：在同一个 JSP 页面中，`PrintWriter`（即 `response.getWriter().write()`）的优先级高于 `JspWriter`（即 `out.println()`） 。
     * *底层内幕*：只有当整张 JSP 页面解析完毕、或者 `out` 缓冲区满了的时候，`out` 里的数据才会一次性冲刷（flush）合并到 `response` 的真实输出流中。因此，不管你在代码里谁写在前面，控制台或浏览器吐数据时，`response.getWriter()` 里的内容永远先蹦出来 ！
