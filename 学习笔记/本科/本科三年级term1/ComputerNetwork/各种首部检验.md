这类题考核的是 **IPv4 首部检验和（Header Checksum）的 16 位二进制反码求和算法**。解题的核心逻辑是：**把 $20\text{ B}$ 固定首部切分成 $10$ 个 $16\text{ bit}$ 的二进制数（检验和字段先填全 `0`），按二进制反码规则全部相加，最后对总和按位取反。**

### 一、 这道题的详细解法与规范步骤

#### 第 1 步：将首部各字段按每 $16\text{ bit}$（一行 $32\text{ bit}$ 拆成左右两半）转为二进制

计算前，先将“首部检验和”字段置为全 `0`：   

- **第 1 行（前 $16\text{ bit}$）**：版本 `4`（`0100`）+ 首部长度 `5`（`0101`）+ 区分服务 `0`（`0000 0000`）   

  $$\rightarrow \texttt{0100 0101 0000 0000}$$

- **第 1 行（后 $16\text{ bit}$）**：总长度 `28`（$16+8+4$）   

  $$\rightarrow \texttt{0000 0000 0001 1100}$$

- **第 2 行（前 $16\text{ bit}$）**：标识 `1`   

  $$\rightarrow \texttt{0000 0000 0000 0001}$$

- **第 2 行（后 $16\text{ bit}$）**：标志 `0`（`000`）+ 片偏移 `0`（`0 0000 0000 0000`）   

  $$\rightarrow \texttt{0000 0000 0000 0000}$$

- **第 3 行（前 $16\text{ bit}$）**：生存时间 TTL `4`（`0000 0100`）+ 协议 `17`（`0001 0001`）   

  $$\rightarrow \texttt{0000 0100 0001 0001}$$

- **第 3 行（后 $16\text{ bit}$）**：首部检验和（计算前先置全 `0`）   

  $$\rightarrow \texttt{0000 0000 0000 0000}$$

- **第 4 行（前 $16\text{ bit}$）**：源地址前两段 `10.12`（`10`=`0000 1010`，`12`=`0000 1100`）   

  $$\rightarrow \texttt{0000 1010 0000 1100}$$

- **第 4 行（后 $16\text{ bit}$）**：源地址后两段 `14.5`（`14`=`0000 1110`，`5`=`0000 0101`）   

  $$\rightarrow \texttt{0000 1110 0000 0101}$$

- **第 5 行（前 $16\text{ bit}$）**：目的地址前两段 `12.6`（`12`=`0000 1100`，`6`=`0000 0110`）   

  $$\rightarrow \texttt{0000 1100 0000 0110}$$

- **第 5 行（后 $16\text{ bit}$）**：目的地址后两段 `7.9`（`7`=`0000 0111`，`9`=`0000 1001`）   

  $$\rightarrow \texttt{0000 0111 0000 1001}$$

#### 第 2 步：对所有非零的 $16\text{ bit}$ 数进行二进制反码求和

> **反码加法规则**：若最高位（第 16 位）向第 17 位产生进位，必须将该进位**回卷（End-around Carry）加到最低位**上。

逐步累加过程如下：

Plaintext

```
    0100 0101 0000 0000   (版本4, 首部长度5, 区分服务0)
  + 0000 0000 0001 1100   (总长度28)
  ---------------------
    0100 0101 0001 1100
  + 0000 0000 0000 0001   (标识1)
  ---------------------
    0100 0101 0001 1101
  + 0000 0100 0001 0001   (TTL=4, 协议=17)
  ---------------------
    0100 1001 0010 1110
  + 0000 1010 0000 1100   (10.12)
  ---------------------
    0101 0011 0011 1010
  + 0000 1110 0000 0101   (14.5)
  ---------------------
    0110 0001 0011 1111
  + 0000 1100 0000 0110   (12.6)
  ---------------------
    0110 1101 0100 0101
  + 0000 0111 0000 1001   (7.9)
  ---------------------
    0111 0100 0100 1110   (最高位无进位产生)
```

#### 第 3 步：对求和结果按位取反

将最终累加和 `0111 0100 0100 1110` 按位取反（`0` 变 `1`，`1` 变 `0`）：

$$\text{首部检验和} = \texttt{1000 1011 1011 0001}$$

*(注：接收端验证时，将包含检验和在内的全部 $10$ 个 $16\text{ bit}$ 数做反码相加，结果必为 `1111 1111 1111 1111`，按位取反后为全 `0`，即判定首部无比特差错。)*

### 二、 与 TCP、UDP 检验的区别

**核心算法完全相同，但检验范围、填充规则和协议细节有显著区别。**

1. **算法相同**：IPv4、TCP、UDP 均使用相同的 **16 位二进制反码求和算法**（检验和置零 $\rightarrow$ $16\text{ bit}$ 反码累加 $\rightarrow$ 进位回卷 $\rightarrow$ 按位取反）。
2. **核心区别对比**：

| **对比维度**        | **IPv4 首部检验和**                                          | **TCP 检验和**                                               | **UDP 检验和**                                               |
| ------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **检验范围**        | **仅检验 IP 首部**（不含数据载荷）                           | **伪首部 + TCP 首部 + TCP 数据部分**                         | **伪首部 + UDP 首部 + UDP 数据部分**                         |
| **是否引入伪首部**  | **否**（首部本身已包含源/目的 IP）                           | **是**（临时拼接 $12\text{ B}$ 伪首部参与计算，不实际发送）  | **是**（临时拼接 $12\text{ B}$ 伪首部参与计算，不实际发送）  |
| **长度补零规则**    | 首部长度恒为 $4\text{ B}$ 整数倍，天然是 $16\text{ bit}$ 整数倍，无需补零 | 数据长度可能为奇数字节，若为奇数，计算时需在末尾**临时补 $1\text{ B}$ 全 `0`**（不发送） | 同 TCP，若总长度为奇数字节，计算时需在末尾**临时补 $1\text{ B}$ 全 `0`**（不发送） |
| **是否强制使用**    | IPv4 **强制**（IPv6 已直接取消该字段）                       | **强制**                                                     | IPv4 中**可选**（不用时填全 `0`）；IPv6 中**强制**           |
| **全 `0` 结果处理** | 直接写入                                                     | 直接写入                                                     | 若算出的检验和恰好为全 `0`，必须改写为**全 `1`**（因全 `0` 已被用于表示“未启用检验”） |
| **出错后动作**      | 直接丢弃该数据报                                             | 丢弃报文段，并依赖**超时/冗余 ACK 触发重传**                 | 直接丢弃该用户数据报，不重传                                 |

> **补充理解（为什么设计成这样）**：IP 路由器每转发一跳都要修改 TTL 并重新计算 IP 首部检验和，因此 IP 层只检首部以保证转发效率；而 TCP/UDP 是端到端协议，引入包含源/目的 IP 和协议号的**伪首部**，可以防止 IP 层路由出错把数据误交给错误的 IP 主机或错误的上层协议。

### 一、 伪首部（Pseudo-Header）怎么构造

在 IPv4 环境下，TCP 和 UDP 计算检验和时，都需要在各自的首部前面**临时拼接一个 $12\text{ B}$（$96\text{ bit}$）的伪首部**。它的核心特征是：**既不向下层递交，也不在网络中实际传输**，仅在发送端计算检验和、接收端验证检验和时在内存中临时构造。

其 $12\text{ B}$ 结构如下（按 $16\text{ bit}$ 为一组切分，共 $6$ 组）：

| **字节偏移** | **字段内容**       | **长度**     | **说明**                                                     |
| ------------ | ------------------ | ------------ | ------------------------------------------------------------ |
| $0 \sim 3$   | **源 IP 地址**     | $4\text{ B}$ | 与 IP 首部中的源 IP 一致（拆成两个 $16\text{ bit}$）         |
| $4 \sim 7$   | **目的 IP 地址**   | $4\text{ B}$ | 与 IP 首部中的目的 IP 一致（拆成两个 $16\text{ bit}$）       |
| $8$          | **全 `0`（保留）** | $1\text{ B}$ | 固定填 `0000 0000`（`0x00`）                                 |
| $9$          | **协议号**         | $1\text{ B}$ | **TCP 填 `6`**（`0x06`），**UDP 填 `17`**（`0x11`）          |
| $10 \sim 11$ | **TCP / UDP 长度** | $2\text{ B}$ | **仅指【TCP/UDP 首部 + 数据载荷】的总字节数，不包含伪首部本身的 $12\text{ B}$** |

> **关键细节（奇数字节补零）**：由于伪首部（$12\text{ B}$）、TCP 首部（$4\text{ B}$ 的整数倍）和 UDP 首部（$8\text{ B}$）都是偶数字节，只要**应用层数据部分是奇数字节**，拼接后的总长度就是奇数。此时必须在数据末尾临时补 $1\text{ B}$ 全 `0`（`0x00`）凑成 $16\text{ bit}$ 整数倍参与计算（该补零字节同样不发送）。

### 二、 UDP 检验和计算实例（含奇数字节补零）

**题目设定**： 主机 `192.168.1.1`（源端口 `1000`）向 `192.168.1.2`（目的端口 `2000`）发送一个 UDP 用户数据报，数据载荷为 $1$ 个 ASCII 字符 `'A'`（十进制 `65`，十六进制 `0x41`）。求 UDP 检验和。

#### 1. 构造各字段并按 $16\text{ bit}$ 分组

- **伪首部（$12\text{ B}$）**：
  - 源 IP `192.168` $\rightarrow$ `1100 0000 1010 1000` (`0xC0A8`)
  - 源 IP `1.1` $\rightarrow$ `0000 0001 0000 0001` (`0x0101`)
  - 目的 IP `192.168` $\rightarrow$ `1100 0000 1010 1000` (`0xC0A8`)
  - 目的 IP `1.2` $\rightarrow$ `0000 0001 0000 0010` (`0x0102`)
  - 保留 `0` + 协议号 `17` $\rightarrow$ `0000 0000 0001 0001` (`0x0011`)
  - UDP 长度：$8\text{ B (UDP首部)} + 1\text{ B (数据)} = 9\text{ B}$ $\rightarrow$ `0000 0000 0000 1001` (`0x0009`)
- **UDP 首部（$8\text{ B}$）**：
  - 源端口 `1000` $\rightarrow$ `0000 0011 1110 1000` (`0x03E8`)
  - 目的端口 `2000` $\rightarrow$ `0000 0111 1101 0000` (`0x07D0`)
  - UDP 长度 `9` $\rightarrow$ `0000 0000 0000 1001` (`0x0009`)
  - UDP 检验和（置零） $\rightarrow$ `0000 0000 0000 0000` (`0x0000`)
- **UDP 数据（$1\text{ B}$ + 临时补 $1\text{ B}$ 零）**：
  - 字符 `'A'` (`0x41`) + 补零 (`0x00`) $\rightarrow$ `0100 0001 0000 0000` (`0x4100`)

#### 2. 16 位二进制反码累加（进位回卷）

Plaintext

```
    1100 0000 1010 1000   (0xC0A8: 192.168)
  + 0000 0001 0000 0001   (0x0101: 1.1)
  ---------------------
    1100 0001 1010 1001   (0xC1A9)
  + 1100 0000 1010 1000   (0xC0A8: 192.168)
  ---------------------
  1 1000 0010 0101 0001   (产生进位 1，回卷加到最低位)
  +                   1
  ---------------------
    1000 0010 0101 0010   (0x8252)
  + 0000 0001 0000 0010   (0x0102: 1.2)
  ---------------------
    1000 0011 0101 0100   (0x8354)
  + 0000 0000 0001 0001   (0x0011: 0 + 协议17)
  ---------------------
    1000 0011 0110 0101   (0x8365)
  + 0000 0000 0000 1001   (0x0009: 伪首部中的UDP长度9)
  ---------------------
    1000 0011 0110 1110   (0x836E)
  + 0000 0011 1110 1000   (0x03E8: 源端口1000)
  ---------------------
    1000 0111 0101 0110   (0x8756)
  + 0000 0111 1101 0000   (0x07D0: 目的端口2000)
  ---------------------
    1000 1111 0010 0110   (0x8F26)
  + 0000 0000 0000 1001   (0x0009: 首部中的UDP长度9)
  ---------------------
    1000 1111 0010 1111   (0x8F2F)
  + 0100 0001 0000 0000   (0x4100: 数据'A' + 补零)
  ---------------------
    1101 0000 0010 1111   (0xD02F)
```

#### 3. 按位取反

对累加和 `1101 0000 0010 1111` (`0xD02F`) 按位取反：

$$\text{UDP 检验和} = \texttt{0010 1111 1101 0000}\quad (\texttt{0x2FD0})$$

*(注：若某次 UDP 计算取反后恰好为全 `0`（`0x0000`），必须强制改写为全 `1`（`0xFFFF`）。因为在反码算术中 `0xFFFF` 与 `0x0000` 等价，而 `0x0000` 被保留用来表示“发送端未计算检验和”。)*

### 三、 TCP 检验和计算实例

**题目设定**： 主机 `10.0.0.1`（源端口 `50000`）向 `10.0.0.2`（目的端口 `80`）发送一个无选项的 TCP 报文段（首部 $20\text{ B}$），序号 `1`，确认号 `2`，标志位 `PSH=1, ACK=1`，窗口大小 `1024`，紧急指针 `0`，携带 $2\text{ B}$ 数据 `"OK"`（`'O'`=`0x4F`，`'K'`=`0x4B`）。求 TCP 检验和。

#### 1. 构造各字段并按 $16\text{ bit}$ 分组

- **伪首部（$12\text{ B}$）**：
  - 源 IP `10.0.0.1` $\rightarrow$ `0000 1010 0000 0000` (`0x0A00`) 和 `0000 0000 0000 0001` (`0x0001`)
  - 目的 IP `10.0.0.2` $\rightarrow$ `0000 1010 0000 0000` (`0x0A00`) 和 `0000 0000 0000 0010` (`0x0002`)
  - 保留 `0` + 协议号 `6` $\rightarrow$ `0000 0000 0000 0110` (`0x0006`)
  - TCP 长度：$20\text{ B (TCP首部)} + 2\text{ B (数据)} = 22\text{ B}$ $\rightarrow$ `0000 0000 0001 0110` (`0x0016`)
- **TCP 首部（$20\text{ B}$，无独立“TCP长度”字段）**：
  - 源端口 `50000` $\rightarrow$ `1100 0011 0101 0000` (`0xC350`)
  - 目的端口 `80` $\rightarrow$ `0000 0000 0101 0000` (`0x0050`)
  - 序号 `1`（$32\text{ bit}$ 拆成两半） $\rightarrow$ `0000 0000 0000 0000` (`0x0000`) 和 `0000 0000 0000 0001` (`0x0001`)
  - 确认号 `2`（$32\text{ bit}$ 拆成两半） $\rightarrow$ `0000 0000 0000 0000` (`0x0000`) 和 `0000 0000 0000 0010` (`0x0002`)
  - 数据偏移 `5`（`0101`）+ 保留（`000000`）+ 标志 `PSH=1, ACK=1`（`011000`） $\rightarrow$ `0101 0000 0001 1000` (`0x5018`)
  - 窗口 `1024` $\rightarrow$ `0000 0100 0000 0000` (`0x0400`)
  - 检验和（置零） $\rightarrow$ `0000 0000 0000 0000` (`0x0000`)
  - 紧急指针 `0` $\rightarrow$ `0000 0000 0000 0000` (`0x0000`)
- **TCP 数据（$2\text{ B}$，偶数长度无需补零）**：
  - `"OK"` $\rightarrow$ `0100 1111 0100 1011` (`0x4F4B`)

#### 2. 16 位二进制反码累加（跳过全 `0` 项）

Plaintext

```
    0000 1010 0000 0000   (0x0A00: 10.0)
  + 0000 0000 0000 0001   (0x0001: 0.1)
  + 0000 1010 0000 0000   (0x0A00: 10.0)
  + 0000 0000 0000 0010   (0x0002: 0.2)
  + 0000 0000 0000 0110   (0x0006: 0 + 协议6)
  + 0000 0000 0001 0110   (0x0016: TCP长度22)
  ---------------------
    0001 0100 0001 1111   (0x141F: 伪首部小计)
  + 1100 0011 0101 0000   (0xC350: 源端口50000)
  ---------------------
    1101 0111 0110 1111   (0xD76F)
  + 0000 0000 0101 0000   (0x0050: 目的端口80)
  ---------------------
    1101 0111 1011 1111   (0xD7BF)
  + 0000 0000 0000 0001   (0x0001: 序号低16位)
  + 0000 0000 0000 0010   (0x0002: 确认号低16位)
  ---------------------
    1101 0111 1100 0010   (0xD7C2)
  + 0101 0000 0001 1000   (0x5018: 数据偏移+标志位)
  ---------------------
  1 0010 0111 1101 1010   (产生进位 1，回卷加到最低位)
  +                   1
  ---------------------
    0010 0111 1101 1011   (0x27DB)
  + 0000 0100 0000 0000   (0x0400: 窗口1024)
  ---------------------
    0010 1011 1101 1011   (0x2BDB)
  + 0100 1111 0100 1011   (0x4F4B: 数据"OK")
  ---------------------
    0111 1011 0010 0110   (0x7B26)
```

#### 3. 按位取反

对累加和 `0111 1011 0010 0110` (`0x7B26`) 按位取反：

$$\text{TCP 检验和} = \texttt{1000 0100 1101 1001}\quad (\texttt{0x84D9})$$
