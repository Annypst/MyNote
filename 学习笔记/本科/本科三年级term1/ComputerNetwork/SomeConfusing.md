**码元（Symbol）**：是一个具体的**物理信号波形**或**状态实体**。

**波特（Baud）**：是一个**频率/速率单位**，表示“每秒传输的码元个数”，即：

$$1 \text{ Baud} = 1 \text{ 码元/秒}$$

$$\text{比特率 (bit/s)} = \text{波特率 (Baud)} \times \text{每个码元携带的比特数 (bit/码元)}$$

### ip首部的检验和与tcp/udp首部检验和有什么区别？算法一样吗？怎么加伪首部

IP 首部检验和与 TCP/UDP 检验和虽然底层数学算法一致，但在**覆盖范围、更新频率和强制性**上有本质区别。以下分三部分详细说明：

### 一、 IP 首部检验和与 TCP/UDP 检验和的区别

| **对比维度** | **IP 首部检验和（IPv4）**                                    | **TCP / UDP 检验和**                                         |
| ------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **检验范围** | **仅覆盖 IP 首部**，不包含数据载荷（Payload）。              | 覆盖 **伪首部 + TCP/UDP 首部 + TCP/UDP 数据部分**（三部分完整参与计算）。 |
| **设计目的** | 保证网络层分组转发时控制信息（如目的 IP、分片偏移）不出错；不检验数据是为了减轻路由器负担。 | 提供**端到端**的差错检测，既检验传输层首部和数据，也通过伪首部确认分组确实送达了正确的目的 IP 和传输层协议。 |
| **更新机制** | **逐跳（Hop-by-Hop）重新计算**。分组每经过一个路由器，生存时间（TTL）减 $1$，首部发生变化，路由器必须重新计算检验和。 | **端到端（End-to-End）计算**。由源主机发送前计算，中间路由器不修改、不检验（NAT 设备除外），直到目的主机才进行验证。 |
| **是否强制** | IPv4 中**强制**使用；**IPv6 中已彻底取消首部检验和**（完全依赖链路层和传输层检验以提高转发速度）。 | **TCP**：IPv4 与 IPv6 中均**强制**使用。  **UDP**：IPv4 中**可选**（不使用时检验和字段全填 `0`）；IPv6 中**强制**使用。 |

### 二、 两者的算法是否一样？

**完全一样**，两者均采用 **16 位二进制反码求和算法（16-bit One's Complement Sum）**。

具体计算步骤如下（以发送方为例）：

1. **清零**：先将首部中的“检验和”字段置为 `0`。
2. **分段与补齐**：将需要检验的全部内容按每 **$16\text{ bit}$（2 字节）\**划分为若干个字。如果总字节数为\**奇数**，则计算时在末尾临时补一个全 `0` 字节（`0x00`）凑成偶数个字节（**注意：补的这个字节仅参与计算，不会实际发送出去**）。
3. **二进制反码求和（循环进位）**：将所有 16 位字相加；若最高位产生进位，则将进位加回到最低位（即“回卷”，End-Around Carry）。
4. **按位取反**：对最终得到的 16 位和**按位取反**（`0` 变 `1`，`1` 变 `0`），将结果填入检验和字段。

*(接收方验证时，将收到的检验范围内容连同检验和字段一起按 16 位反码求和；若无差错，最终结果必定为全 `1`，即 `0xFFFF`。)*

### 三、 伪首部（Pseudo-Header）的结构与添加方式

#### 1. 伪首部的格式（以 IPv4 为例，共 12 字节 / 96 bit）

| **字节偏移**     | **0 ~ 7 bit (1 字节)**     | **8 ~ 15 bit (1 字节)**                          | **16 ~ 23 bit (1 字节)**                                | **24 ~ 31 bit (1 字节)** |
| ---------------- | -------------------------- | ------------------------------------------------ | ------------------------------------------------------- | ------------------------ |
| **第 0~3 字节**  | **源 IP 地址**（32 bit）   |                                                  |                                                         |                          |
| **第 4~7 字节**  | **目的 IP 地址**（32 bit） |                                                  |                                                         |                          |
| **第 8~11 字节** | **全 `0` 填充**（8 bit）   | **协议号**（8 bit）  *(TCP 为 `6`，UDP 为 `17`)* | **TCP / UDP 长度**（16 bit）  *(首部 + 数据的总字节数)* |                          |

*(注：计算 UDP 检验和时，“UDP 长度”字段实际上在伪首部和 UDP 首部中各参与了一次计算；且无论是 TCP 还是 UDP，伪首部里的长度字段**均不包含**伪首部自身的 12 字节。)*

#### 2. 怎么“加”伪首部？（关键概念）

- **只在内存中临时拼接，绝不实际传输**：伪首部既不是 IP 首部，也不是真正的 TCP/UDP 首部。它**不会**被向下传递给 IP 层，也**不会**出现在网络链路传输的比特流中。
- **收发双方的操作过程**：
  - **发送方**：传输层在内存中临时开辟一段缓冲区，把这 12 字节的伪首部拼接到 TCP/UDP 报文段的最前面，算出 16 位检验和并填入 TCP/UDP 首部后，**立即丢弃伪首部**，只把真正的 TCP/UDP 报文段交给网络层。
  - **接收方**：网络层剥去 IP 首部后，把其中的“源 IP、目的 IP、协议号”连同 TCP/UDP 报文段一起交给传输层；传输层在内存中重新拼出完全相同的 12 字节伪首部，执行 16 位反码求和验证，验证通过后同样丢弃伪首部。
