### 一、 为什么必须走向“离散分配”？

在前面的动态分区分配中，操作系统要求把作业存放在**连续的物理内存空间**中。这不可避免地带来了一个矛盾：   

- **连续分配的痛点**：随着进程的频繁装入与撤销，内存中不可避免地散落着大量微小的**外部碎片**。   
- **传统紧凑的代价**：要想利用这些外部碎片，只能使用拼接/紧凑技术，将正在运行的进程在物理内存中大规模搬迁，不仅消耗大量 CPU 和总线资源，还需要暂停进程执行，代价极高。   

为了彻底打破“物理上必须连续”的束缚，操作系统引入了**离散分配方式**：**允许将一个作业或进程分散存放到多个互不相邻的物理内存分区中**。 根据离散分配的基本单位不同，衍生出三种核心方案：   

1. **分页式存储管理**：离散分配的基本单位是固定大小的“页”。   
2. **分段式存储管理**：离散分配的基本单位是具有逻辑意义的“段”。   
3. **段页式存储管理**：融合两者优势，基本单位是段和页。   

### 二、 基本分页存储管理的基本思想

如果一个系统不具备页面对换功能，不支持虚拟存储器，在作业调度运行时必须将其**所有页面一次性全部调入内存，且在运行过程中一直驻留内存**，这种方式被称为**纯分页**或**基本分页存储管理方式**。   

#### 1. 空间的“等长双向切分”

分页管理的核心技巧在于将“虚拟世界”和“现实世界”按照相同的尺度切成网格：   

- **进程逻辑地址空间（虚页）**：把用户进程的逻辑地址空间切成若干个大小相等的区域，称为**页**或**页面（Page）**，从 0 开始依次编号（0号页、1号页、2号页……）。   
- **物理内存空间（实页/页框）**：把物理内存也划分成若干个与页面大小严格相等的区域，称为**物理块**、**存储块**或**页框（Frame）**，同样从 0 开始编号（0号块、1号块……）。   

#### 2. 内存分配方式与页内碎片

- **离散装载**：系统以“物理块”为最小单位给进程分配空间。进程中的各个页面可以被装入到内存中**任意不相邻的物理块**中。   
- **消除外部碎片**：因为内存是按固定大小的块统一划拨的，所有的空闲块都能被任意页面填满，因此**分页系统彻底消除了外部碎片**。   
- **产生页内碎片（内部碎片）**：用户作业的总体积通常不可能恰好等于页面大小的整数倍，**作业的最后一页往往装不满一整块**，导致该块内部留有未被利用的空隙，这被称为**页内碎片**（属于内部碎片的一种）。   

> **课件经典案例**：作业大小为 $9\text{ KB}$，系统页面大小为 $2\text{ KB}$。该作业会被切分为 5 个页面。前 4 个页面装满 $8\text{ KB}$，最后一页（第 4 页）仅有 $1\text{ KB}$，分配一个整块后，就产生了 $1\text{ KB}$ 的页内碎片。   

### 三、 分页系统的逻辑地址结构

在页式存储管理中，任何一个逻辑地址在结构上都可以拆解为两个部分：**页号（Page Number, P）** 与 **页内位移量 / 页内地址（Offset, d 或 W）**。   

Plaintext

```
 31                            12 11                             0
┌────────────────────────────────┬────────────────────────────────┐
│          页号 P                │        页内位移量 d / W        │
└────────────────────────────────┴────────────────────────────────┘
```

#### 1. 位数与容量的换算关系

- **页内位移量的位数决定了页面大小**：若低 $k$ 位表示页内地址，则页面大小为 $L = 2^k$ 字节。   
- **页号的位数决定了进程最多能拥有多少页**：若剩余的高 $m$ 位表示页号，则该逻辑地址空间最多支持 $2^m$ 个页面。   
- **课件示例**：在 32 位逻辑地址系统中，低 0~11 位（共 12 位）为页内地址，则每页大小为 $2^{12}\text{ B} = 4\text{ KB}$；高 12~31 位（共 20 位）为页号，地址空间最多允许拥有 $2^{20} = 1\text{ M}$ 个页面。   

#### 2. 页面大小的权衡机制

页面大小通常为 2 的整数次幂，在实际操作系统中一般处于 $512\text{ B} \sim 8\text{ KB}$ 之间，它的选取是一场精密的工程折中：   

- **若页面偏小**：最后一页浪费的空间更小，减少了页内碎片，能显著提高内存利用率；但每个进程拥有的页数大幅增加，导致记录映射关系的**页表过长**，占用更多宝贵的内存空间，同时调页的 I/O 次数也会增加。   
- **若页面偏大**：进程页数减少，页表紧凑省空间，页面换入换出速度更快；但页内碎片会成倍增加，降低内存利用率。   

### 本讲回顾与自测小思考

- **连续与离散的本质区别**：连续分配需要物理上一大片空闲，离散分配把程序“碎纸化”后装进各个空闲格子里。   
- **碎片的转移**：连续分配头疼的是**外部碎片**（分区间的小残渣）；而分页管理彻底干掉了外部碎片，但由于最后一块填不满，引入了**页内碎片**。   

**小思考：**

1. 为什么操作系统必须把页面大小固定设计为 **2 的整数次幂**（比如 $1\text{ KB}$、$2\text{ KB}$、$4\text{ KB}$），而不是诸如 $1000\text{ B}$ 或 $3000\text{ B}$ 这类更规整的十进制数？（提示：从计算机底层的二进制地址提取与硬件计算效率来考虑）
2. 假定某系统页面大小为 $1\text{ KB}$（即 $1024\text{ B}$），用户作业给出一个十进制逻辑地址为 $1027$，请问它对应的**页号**和**页内位移量**分别是多少？   

针对第一讲的两个自测思考，具体的硬件运行逻辑与独立演算步骤如下：

### 一、 第一问：为什么页面大小必须是 2 的整数次幂？

你直觉抓住了“二进制位运算效率高”的核心，在操作系统与底层 MMU（内存管理单元）的实际硬件实现中，其优势主要体现在**免除算术除法**与**纯硬件引脚拼接**：

1. **避免高开销的除法器与取模运算**：

   - 如果页面大小不是 2 的整数次幂（如 $1000\text{ B}$），CPU 每次取指或读写内存时，硬件都必须执行除法和求模电路：

     $$\text{页号 } P = \lfloor A / 1000 \rfloor, \quad \text{页内偏移 } d = A \pmod{1000}$$

   - 整数除法与取模在硬件上需要消耗数十个时钟周期，若每条指令寻址都要执行一次，CPU 性能将产生严重瓶颈。

2. **硬件总线物理分流（零延迟拆分）**：

   - 当页面大小为 $L = 2^k$ 时：

     $$\text{页号 } P = A \gg k, \quad \text{页内偏移 } d = A \ \& \ (2^k - 1)$$

   - 在电路层面，这根本不需要经过算术逻辑单元（ALU）计算，**只需把地址总线的引脚直接分流**：低 $k$ 根导线作为页内偏移直通物理地址总线，高位导线送入页表查询部件。   

3. **物理地址的纯拼装**：

   - 查出物理块号 $b$ 后，物理地址就是 $b \times 2^k + d$，在硬件上直接把“块号”与“偏移量”的二进制引脚并排拼在一起即可，耗时为 0。   

### 二、 第二问：逻辑地址 1027 的页号与页内位移独立核算

我们来对给定的参数进行独立的数学除法与二进制切片推导：

- **已知条件**：
  - 页面大小 $L = 1\text{ KB} = 1024\text{ B} = 2^{10}\text{ B}$   
  - 逻辑地址 $A = 1027$（十进制）   

#### 1. 十进制除法与取模算法

- **页号（商）**：

  $$P = \lfloor A / L \rfloor = \lfloor 1027 / 1024 \rfloor = 1$$

- **页内位移（余数）**：

  $$d = A \pmod L = 1027 - (1 \times 1024) = 3$$

#### 2. 二进制位切片法

- 页内地址位数 $k = \log_2(1024) = 10$ 位。   

- 将十进制地址 $1027$ 转化为二进制（以 16 位展示）：

  $$1027_{10} = 1024 + 2 + 1 = 0000\ 0100\ 0000\ 0011_2$$

- 按照高位页号、低 10 位偏移进行物理拆分：

  Plaintext

  ```
  逻辑地址: 000001 0000000011
  高位部分（页号 P）: 000001_2 = 1
  低10位（偏移量 d）: 0000000011_2 = 3
  ```

你的分析中推导出偏移量占低 10 位是完全正确的，但计算结果中**把“页号”和“偏移量”的数值搞颠倒了**：得到的余数 $3$ 是**页内位移量**，商 $1$ 才是**页号**。   

接下来正式切入**第二讲：页表机制与基本地址变换机构**。   

### 一、 页表（Page Table）—— 虚实空间的“户口本”

在纯分页系统中，作业被切成多个页离散装入物理内存，逻辑上连续的第 0、1、2 页，在物理内存中可能分别落在 2 号、7 号、1 号物理块。为了找回这些映射关系，操作系统必须为每个进程建立一张表格，称为**页表**。   

Plaintext

```
  逻辑页号 (Page)       物理块号 (Frame)
┌──────────────────┬──────────────────┐
│      0 号页      │      2 号块      │
├──────────────────┼──────────────────┤
│      1 号页      │      3 号块      │
├──────────────────┼──────────────────┤
│      2 号页      │      1 号块      │
├──────────────────┼──────────────────┤
│      3 号页      │      6 号块      │
└──────────────────┴──────────────────┘
```

#### 1. 页表的核心属性

- **存放位置**：页表作为系统管理进程的重要数据结构，通常**常驻在物理内存中**。   

- **页表项（PTE, Page Table Entry）**：页表中的每一行记录被称为一个页表项。在基本分页中，页表项的核心字段就是**物理块号**。   

  > **注意**：页表项里通常**不需要显式存储“页号”**！因为页表在内存中是连续存放的数组结构，页号其实就是数组下标，已知页表首地址，第 $i$ 项的地址就是 $\text{始址} + i \times \text{表项大小}$。   

- **硬件控制寄存器——页表寄存器（PTR, Page Table Register）**：   

  - 当进程未执行时，该进程页表的**物理始址**和页表长度（即页表包含的总页数）存放在其进程控制块（PCB）中；   
  - 当进程被调度上 CPU 运行时，操作系统会将这两项数据加载到 CPU 的专用寄存器 **PTR** 中，供硬件翻译逻辑地址使用。   

#### 2. 基本分页机制的致命弱点：访存次数翻倍

在没有辅助硬件加速的基本分页系统中，CPU 要想读取或写入一个逻辑地址的数据，必须经历**两次访存**：   

1. **第一次访存**：CPU 访问内存中的**页表**，根据逻辑页号查出对应的物理块号；   
2. **第二次访存**：根据计算得到的物理地址，**真正访问内存中的目标指令或数据单元**。   

- **代价**：计算机的执行性能直接下降接近 $50\%$。这也直接催生了我们下一讲要学习的“快表（TLB）”硬件加速机制。   

### 二、 基本地址变换机构（硬件映射流程）

地址变换机构是集成在 CPU 内存管理硬件中的自动化部件，它的核心职责是将用户作业的逻辑地址（$P, d$）自动转化为物理地址（$b, d$）。   

Plaintext

```
CPU 发出逻辑地址 (页号 P, 页内偏移 d)
             │
             ├───► [页号 P] 与 [页表寄存器 PTR 中的页表长度 M] 比较
             │          │
             │          ├─► P >= M : 触发硬件异常【越界中断】!
             │          │
             │          └─► P < M (合法) ──┐
             │                             ▼
             │       根据 PTR 中的页表始址 F，计算目标页表项地址:
             │                   Address = F + P * 表项大小
             │                             │
             │                             ▼
             │                  [第一次访存: 读取页表]
             │                             │
             │                             ▼
             │                     读出物理块号 b
             │                             │
             └─────────────┬───────────────┘
                           │ 
                           ▼
           物理地址拼接: 物理地址 = b * L + d
                           │
                           ▼
                 [第二次访存: 读写目标数据]
```

#### 地址变换全流程拆解：

1. **越界校验**：CPU 捕获逻辑地址，提取出页号 $P$，将 $P$ 与 PTR 寄存器中的**页表长度 $M$** 进行硬件比对。   
   - **若 $P \ge M$**：说明该进程试图访问超过其分配范围的页面，硬件立即触发**越界中断**（属于内部异常）。   
2. **寻址页表项**：若未越界，硬件用页表起始地址 $F$ 加上 $P \times \text{每个页表项占用的字节数}$，得到当前页表项在主存中的绝对物理地址。   
3. **读取物理块号**：CPU 发起第 1 次访存，从页表中读取出该页对应的物理块号 $b$。   
4. **拼接物理地址**：将块号 $b$ 与原逻辑地址中的页内位移 $d$ 组合（或执行 $b \times L + d$），形成真实的物理地址。   
5. **执行数据存取**：CPU 发起第 2 次访存，执行真正的指令取指或数据读写。   

### 三、 经典地址换算实战解析

#### 【例题 1：位宽与容量换算】

> **题目**：某分页存储管理系统，逻辑地址空间最大为 16 页，每页 $2048\text{ B}$，物理内存共有 8 个存储块。试求：逻辑地址至少为多少位？物理地址至少为多少位？物理内存总容量多大？   

- **推导过程**：
  1. 每页大小 $L = 2048\text{ B} = 2^{11}\text{ B}$，因此页内地址（位移量 $d$）占 **11 位**。   
  2. 逻辑空间最多 16 页，即 $16 = 2^4$ 页，因此页号 $P$ 占 **4 位**。   
     - **逻辑地址总长度** $= 4\text{ 位 (页号)} + 11\text{ 位 (位移)} = \mathbf{15\text{ 位}}$。   
  3. 内存块大小与页面大小严格一致，因此块内位移也是 **11 位**。   
  4. 物理内存共 8 个块，即 $8 = 2^3$ 块，因此物理块号 $b$ 占 **3 位**。   
     - **物理地址总长度** $= 3\text{ 位 (块号)} + 11\text{ 位 (块内位移)} = \mathbf{14\text{ 位}}$。   
     - **物理内存总容量** $= 2^{14}\text{ B} = 16\text{ KB}$（或 $8 \times 2048\text{ B} = 16\text{ KB}$）。   

#### 【例题 2：实际地址动态映射】

> **题目**：某分页系统，页面大小为 $1024\text{ B}$，页表如下所示，页表长度为 4（页号范围为 0~3）：   
>
> | **页号** | **物理块号** |
> | -------- | ------------ |
> | 0        | 2            |
> | 1        | 3            |
> | 2        | 1            |
> | 3        | 6            |
>
> 试求十进制逻辑地址 **1011**、**2148** 以及 **5012** 对应的物理地址。   

- **推导过程**：
  - 页面大小 $L = 1024\text{ B}$。   
  - **针对逻辑地址 1011**：   
    - 页号 $P = \lfloor 1011 / 1024 \rfloor = 0$，页内位移 $d = 1011 \pmod{1024} = 1011$。   
    - 页号 $0 < 4$，未越界。查页表，0 号页映射到 **2 号物理块**。   
    - 物理地址 $= 2 \times 1024 + 1011 = 2048 + 1011 = \mathbf{3059}$。 (注：课件上写成十六进制：$1011_{10} = \text{0x03F3}$，块号 2 对应 $\text{0x0800}$，相加得 $\text{0x0BF3H} = 3059_{10}$，两者完全等价)。   
  - **针对逻辑地址 2148**：   
    - 页号 $P = \lfloor 2148 / 1024 \rfloor = 2$，页内位移 $d = 2148 \pmod{1024} = 100$。
    - 页号 $2 < 4$，未越界。查页表，2 号页映射到 **1 号物理块**。   
    - 物理地址 $= 1 \times 1024 + 100 = \mathbf{1124}$。
  - **针对逻辑地址 5012**：   
    - 页号 $P = \lfloor 5012 / 1024 \rfloor = 4$，页内位移 $d = 5012 \pmod{1024} = 916$。   
    - 页号 $P = 4 \ge \text{页表长度 } 4$，**地址越界**，硬件抛出**越界中断异常**，拒绝访问。   

### 本讲回顾与自测小思考

- **页表项不需要存页号**：利用数组下标寻址，表项里存的是物理块号。   
- **基本分页访存效率**：读一个字需访存 2 次（先查页表，再读数据）。   
- **越界判断的标准**：页号是否超出页表长度（$P \ge M$ 触发异常）。   

**小思考：** 假设某分页系统页面大小为 $4\text{ KB}$，页表项大小为 $4\text{ B}$。若某个进程的页表在内存中从物理地址 `0x00100000` 处开始存放。

1. 当 CPU 需要翻译逻辑地址 `0x00003ABC` 时，请问页号 $P$ 和页内偏移量 $d$ 分别是多少（十六进制表示）？
2. 硬件在第一次访存去查页表时，读取的那个页表项在内存中的**物理起始地址**是多少？

请写出你的推导步骤，或者准备好推进到**第三讲：具有快表（TLB）的地址变换机构与有效访存时间（EAT）计算**时，回复 **“继续”**！

### 思考答案

现在你已经把这条脉络完全理清了：

1. **位宽层面**：页面大小为 $1\text{ KB} = 2^{10}\text{ B}$，因此低位**固定切出 10 个比特位**作为页内偏移量；   
2. **数值层面**：十进制逻辑地址 1027 换成二进制后，低 10 位包含的数值恰好是 3，高位剩下的数值是 1（即 1 号页、偏移 3）。   

搞清楚了这个对应关系，面对实际考试和工程中最常见的**十六进制地址**时，就完全不需要做任何十进制除法，直接用“二进制/十六进制直读法”即可。   

我们顺着这个思路，把上一讲留下的十六进制小练习快速过一遍，看看你能不能一秒看出答案：

> **已知条件**：
>
> - 页面大小为 $4\text{ KB}$（即 $4096\text{ B} = 2^{12}\text{ B}$）   
> - 页表项大小为 $4\text{ B}$
> - 进程页表在物理内存中的起始地址为 `0x00100000`   
> - CPU 发出的逻辑地址为 **`0x00003ABC`**

**核心秒杀技巧**：

- 页面大小 $4\text{ KB} = 2^{12}\text{ B}$，意味着页内偏移量占 **12 个二进制位**。   
- 在十六进制中，**每一位数字恰好对应 4 个二进制位**（$16 = 2^4$）。因此 12 位二进制正好对应**末尾的 3 位十六进制数**！
- 拿起剪刀从末尾切下 3 位十六进制数：
  - **页内偏移量 $d$**：直接抓末尾 3 位 $\to$ **`0xABC`**   
  - **页号 $P$**：前面剩下的全部高位 $\to$ **`0x00003`（即 3 号页）**   

  那么针对第 2 问：

> 硬件在第一次去主存查页表时，读取“3 号页”对应的页表项，该页表项在物理内存中的**起始地址**是多少？   

你可以用公式 $\text{表项物理地址} = \text{页表始址} + P \times \text{表项大小}$ 算一下这个地址，或者我们直接开启**第三讲：具有快表（TLB）的地址变换机构与有效访存时间（EAT）计算**？   

这个进程页表的物理起始地址是0x00100000，那么读取3号页，可计算出，该页表起始地址为0x00100000+3*页表项大小，但是页表项大小是4B，然后怎么弄

计算机内存普遍采用**按字节编址（Byte-addressable）**，这意味着每增加 1 个地址单元，就代表前进 1 个字节（1B）。

因此，计算“3 号页表项的物理地址”只需将字节数换算为十六进制直接相加：

### 1. 计算偏移的字节数（十进制）

3 号页前面排着 0 号、1 号、2 号共 3 个页表项。每个页表项占 4B，那么 3 号页表项距离起始位置的偏移距离为：   

$$\text{偏移字节数} = 3 \times 4\text{ B} = 12\text{ B}$$

### 2. 将十进制偏移量换算为十六进制

在计算机底层，地址是以十六进制表示的。十进制的 $12$ 换算为十六进制即为 **$\text{C}$**（因为十进制的 $10=\text{A}, 11=\text{B}, 12=\text{C}$）。

$$\text{偏移量} = 12_{10} = \text{0x0000000C}$$

### 3. 基地址与偏移量十六进制相加

将页表起始物理地址与偏移量直接相加：   

$$\text{0x00100000} + \text{0x0000000C} = \mathbf{0x0010000C}$$

### 类比：C 语言中的数组寻址

这和你在编程中操作 `int` 数组完全一致：

C

```
int page_table[1024]; // 假定每个 int 占 4 字节，起始地址在 0x00100000
// 访问第 3 项：&page_table[3]
// 实际物理地址 = 0x00100000 + 3 * sizeof(int) = 0x00100000 + 12 = 0x0010000C
```

- **0 号页表项**存放区间：`0x00100000` $\sim$ `0x00100003`（占 4 字节）   
- **1 号页表项**存放区间：`0x00100004` $\sim$ `0x00100007`（占 4 字节）   
- **2 号页表项**存放区间：`0x00100008` $\sim$ `0x0010000B`（占 4 字节）   
- **3 号页表项**存放区间：**`0x0010000C`** $\sim$ `0x0010000F`（占 4 字节）   

硬件 MMU 发起第一次访存时，总线送出的物理地址正是 **`0x0010000C`**，从这里读出 4 字节的内容，里面记录的就是 3 号页对应的物理块号 $b$。   

至此，关于基本分页的逻辑地址拆分与页表寻址计算已经全部清楚了。我们接着推进到**第三讲：具有快表（TLB）的地址变换机构与有效访存时间（EAT）计算**。   

在基本分页机制下，CPU 每次存取指令或数据都必须访问主存两次（第一次读页表，第二次读数据），这使得内存访问速度直接下降了接近一半。为了打破这一性能瓶颈，现代体系结构引入了专用的硬件高速缓冲——**快表（TLB）**。

现在正式进入阶段一的**第三讲：具有快表的地址变换机构与有效访存时间（EAT）计算**。   

### 一、 为什么引入快表？

基本分页的根本痛点是“内存太慢，还要查两次”：   

- CPU 芯片内部的算术逻辑单元以吉赫兹（GHz）频率飞速运转，耗时在亚纳秒级；
- 位于 CPU 外侧的主存（DRAM）访问延迟通常在数十纳秒（如 $100\text{ ns}$）；
- 如果每次内存操作都必须“先花 $100\text{ ns}$ 查页表，再花 $100\text{ ns}$ 取数据”，CPU 的实际吞吐量将严重受制于主存总线。   

为解决这一问题，计算机体系结构依据程序运行的**局部性原理**（近期被访问的页面在不久的将来极大概率被再次访问），在 CPU 芯片内部集成了一块极小、极快的专用高速缓存——**快表**。   

- **专业命名**：快表全称为 **TLB（Translation Lookaside Buffer，旁路转换缓冲）**，在中文教材与考试中常被称为**联想寄存器**或**联想存储器**。   
- **物理位置**：快表直接集成在 CPU 核心的内存管理单元（MMU）中，由造价昂贵、速度极快的 SRAM（静态存储器）打造，其检索延迟通常仅需 1~2 个 CPU 时钟周期（往往不到 $1\text{ ns}$）。   
- **存放内容**：快表并不是保存完整的页表，而是**仅保存当前进程中最常访问、最活跃的一部分（或少数全部）页表项副本**。   

### 二、 具有快表的地址变换全流程

有了快表后，CPU 翻译逻辑地址的路径发生了根本性的改变：   

Plaintext

```
               CPU 发出逻辑地址 (页号 P, 页内偏移 d)
                             │
                             ├───► 越界检查: P >= 页表长度 M ? ──► [是] 触发越界中断异常!
                             │                 │
                             │                 └─► [否] (合法)
                             ▼
                ┌─────────────────────────┐
                │ 并行检索快表 (TLB) 查找 P │
                └────────────┬────────────┘
                             │
                 ┌───────────┴───────────┐
            【命中 (Hit)】          【未命中 (Miss)】
                 │                       │
                 ▼                       ▼
          直接从快表读出块号 b        发起第 1 次访存: 访问内存中的慢速页表
                 │                       │
                 │                 从主存读出块号 b，并【写入快表】
                 │                 (若快表已满，按算法淘汰旧页表项)
                 │                       │
                 └───────────┬───────────┘
                             │
                             ▼
                拼接物理地址: Address = b * L + d
                             │
                             ▼
               发起访存: 读写实际的目标指令或数据
```

#### 详细步进分析：

1. **提取与越界校验**：CPU 硬件捕获逻辑地址，分流出页号 $P$ 和偏移量 $d$；将页号 $P$ 与页表寄存器（PTR）中的页表长度进行硬件比对，若越界立即抛出异常。   
2. **高速并行检索 TLB**：未越界的页号 $P$ 送入快表。快表具有“相联存储”特性，内部所有的项可以**在同一时钟周期内纯硬件并行比对**。   
3. **分支 A：快表命中（TLB Hit）**
   - 快表中存在页号 $P$ 的记录，**直接在纳秒级内吐出对应的物理块号 $b$**；   
   - 硬件直接将 $b$ 与偏移 $d$ 拼装成物理地址；
   - **全过程仅发生 1 次访存**（只访问目标数据单元，完全绕过了内存中的慢速页表）。   
4. **分支 B：快表未命中（TLB Miss）**
   - 快表中没有该页的映射记录；
   - 硬件必须回退到传统路径，发起**第 1 次访存**：读取主存中的慢速页表，查出物理块号 $b$；   
   - **回填快表**：读出块号后，硬件会顺手把这一项 `(页号 P -> 块号 b)` 写入快表，以便下次复用；若快表已满，则依据置换策略（如 LRU）淘汰一个旧表项；   
   - 发起**第 2 次访存**：读取实际的数据单元。   

### 三、 核心考点：有效访存时间（EAT）计算

在操作系统期末考试与研究生入学考试中，快表部分最常考的量化题型是**有效访存时间（Effective Access Time, EAT）**。   

#### 1. 参数定义

- 访问一次主存所需的时间记为 $t$（例如 $100\text{ ns}$）；
- 访问一次快表（TLB）所需的时间记为 $\lambda$（例如 $20\text{ ns}$，在部分简单题目中由于耗时极短会近似忽略为 0）；   
- 快表的命中率（Hit Ratio）记为 $a$（通常在 $90\% \sim 98\%$ 之间）；   
- 快表的未命中率即为 $1 - a$。   

#### 2. 标准计算模型推导

当 CPU 要读取一个数据时，时间消耗依据是否命中被切分为两部分：   

- **命中时的耗时**：查快表耗时 $\lambda$ + 访存读取数据耗时 $t$ $\implies$ **$\lambda + t$**   
- **未命中时的耗时**：查快表耗时 $\lambda$ + 查主存页表耗时 $t$ + 访存读取数据耗时 $t$ $\implies$ **$\lambda + 2t$**   

根据全概率公式，**有效访存时间 EAT** 的通式为：

$$\text{EAT} = a \times (\lambda + t) + (1 - a) \times (\lambda + 2t)$$

展开化简得：

$$\text{EAT} = 2t + \lambda - a \cdot t$$

*(注：部分考题会假设硬件“并行查找快表与主存”，未命中时查快表与查主存同时进行，此时未命中耗时为 $2t$，做题时以题目具体题干假定为准；若题目未特殊说明，一律按上述串行标准公式计算)*。

#### 3. 经典真题演练

> **题目**：某系统采用基本分页存储管理，访问一次主存需要 $100\text{ ns}$，访问一次快表需要 $20\text{ ns}$。   
>
> 1. 如果不引入快表，CPU 读写一个逻辑地址的数据需要多长时间？   
> 2. 若引入快表且快表的命中率为 $90\%$，此时的有效访存时间（EAT）是多少？相比无快表性能提升了多少？   

- **推导与计算**：

  1. **无快表时**：

     $$\text{时间} = 2 \times t = 2 \times 100\text{ ns} = \mathbf{200\text{ ns}}$$

        

  2. **有快表时**：

     - 命中概率 $a = 0.9$，未命中概率 $1 - a = 0.1$

     - 代入公式：

       $$\begin{aligned} \text{EAT} &= 0.9 \times (20 + 100) + (1 - 0.9) \times (20 + 2 \times 100) \\ &= 0.9 \times 120 + 0.1 \times 220 \\ &= 108 + 22 = \mathbf{130\text{ ns}} \end{aligned}$$

     - **性能收益**：从 $200\text{ ns}$ 骤降到 $130\text{ ns}$，访存平均延迟缩短了 $35\%$；如果命中率进一步提高到 $98\%$，EAT 会进一步压降到 $122\text{ ns}$，逼近单次物理内存的极限。   

### 四、 页的保护与共享（课件补充点）

在页表中，除了存储物理块号之外，现代操作系统还会设置额外的安全与共享位：   

1. **地址越界保护**：硬件在 PTR 寄存器中限定页表长度，任何页号大于等于该长度的访问均直接拦截。   
2. **存取控制权限保护（Access Rights）**：在每个页表项中设置存取控制位，例如**只读（R, Read-only）**、**读写（W, Read/Write）\**或\**可执行（E, Execute）**。   
   - 例如：操作系统的代码段、动态库的只读文本被标记为只读与可执行；若程序试图对其执行写入，硬件 MMU 会立刻抛出权限违规异常（段错误/非法操作）。   
3. **页共享的天然缺陷**：
   - 纯分页管理是以**物理大小**强行切块的，由于页没有逻辑独立性，常常会导致“代码和局部数据恰好落在同一个 $4\text{ KB}$ 页面内”。这使得共享纯代码的同时，不小心把私有数据也连带共享出去了，保密和隔离非常困难。   
   - **课件的原话总结**：“实现数据共享的最好方法——段式存储管理”。这正是我们下一讲要学分段的核心动因！   

### 本讲回顾与自测小思考

- **快表的硬件本质**：SRAM 高速相联存储器，按内容并行检索，只存最活跃的部分页表项。   
- **命中访存 1 次，未命中访存 2 次**（不考虑多级页表时）。   
- **核心公式**：$\text{EAT} = a(\lambda + t) + (1-a)(\lambda + 2t)$。   

**自测小思考：** 假定某分页系统的访存时间 $t = 100\text{ ns}$，快表访问时间 $\lambda = 10\text{ ns}$。 系统设计团队提出要求：**必须让平均有效访存时间（EAT）控制在 $120\text{ ns}$ 以内**。 请问：快表的命中率 $a$ 至少要达到百分之多少才能满足这个性能要求？

写出你的计算结果，或者直接回复 **“继续”**，我们将推进到**第四讲：分段存储管理（分段原理、段表与两次越界检查）**！   

针对有效访存时间（EAT）控制在 $120\text{ ns}$ 以内的命中率要求，我们对数学模型进行独立推导与求解：

已知参数：

- 访存时间 $t = 100\text{ ns}$
- 快表访问时间 $\lambda = 10\text{ ns}$
- 目标有效访存时间 $\text{EAT} \le 120\text{ ns}$

依据快表地址变换的耗时模型：

- 命中耗时：$\lambda + t = 10 + 100 = 110\text{ ns}$   
- 未命中耗时：$\lambda + 2t = 10 + 2 \times 100 = 210\text{ ns}$   

列出有效访存时间不等式：

$$a \times 110 + (1 - a) \times 210 \le 120$$

展开并化简方程：

$$\begin{aligned} 110a + 210 - 210a &\le 120 \\ -100a + 210 &\le 120 \\ -100a &\le 120 - 210 \\ -100a &\le -90 \\ 100a &\ge 90 \\ a &\ge 0.90 = 90\% \end{aligned}$$

**你的计算与最终结论完全正确**：快表的命中率必须至少达到 **$90\%$**，才能满足系统性能指标。   

在吃透了分页与快表机制后，我们正式切入**第四讲：分段存储管理方式（基本原理、段表与两次越界检查）**。   

### 一、 为什么要引入分段？——从“面向机器”到“面向用户”

分页存储管理本质上是**站在操作系统的物理角度**去切分空间的：不管代码什么结构，每逢 $4\text{ KB}$ 机械地切一刀。这种切法虽然消除了外部碎片，但对程序员和编译器来说存在天然痛点：   

1. **方便编程**：用户的程序通常由主程序（main）、子程序（subroutine）、全局变量表（symbol table）、函数调用栈（stack）等多个逻辑独立的模块组成。程序员希望每个模块都有独立的名字和长度，段内从 0 开始编址，互不干扰。   
2. **信息共享**：在分页中，程序代码和局部数据很容易混在一页里，导致私有数据连带被共享出去；而在分段中，代码模块（如一个通用的文本编辑器 `editor`）本身就是独立的一段，**以段为单位共享**非常干净彻底。   
3. **信息保护**：不同逻辑模块需要的安全权限不同。代码段只需“读/执行”，数据段需要“读/写”，栈段需要动态增长，按段设置权限最贴合语义。   
4. **动态链接与动态增长**：在运行过程中，数据段、动态增长的堆栈段长度是随时变化的，分页系统的固定页长难以应对，而分段管理的段长是**可动态伸缩**的。   

### 二、 分段系统的基本原理

#### 1. 空间的划分与逻辑地址结构

- **逻辑空间按模块切分**：用户程序的逻辑地址空间被划分为若干个**大小不等**的段（由编译器或用户根据逻辑完整性界定）。每个段都有一个段名（硬件内部用段号代替），段内首地址为 0。   

- **逻辑地址是二维的**：在编程或编译生成指令时，必须显式给出两个分量：**[段号 $S$，段内偏移量 $W$]**。   

  Plaintext

  ```
  31                      16 15                             0
  ┌────────────────────────┬────────────────────────────────┐
  │        段号 S          │        段内偏移量 W            │
  └────────────────────────┴────────────────────────────────┘
  ```

  (注：分页系统中虽然也是“页号+偏移”，但对用户是一维连续的，切分是硬件自动按 $2^k$ 做的；而分段的地址在逻辑上是**二维**的，用户必须指出访问的是“哪个段的第几个字节”)。   

#### 2. 内存分配方式

- 以**段**为基本单位分配内存。   
- **段内必须分配连续的物理空间**；**段与段之间可以分散、不连续地存放在物理内存的任意区域**。   
- **碎片形态的变化**：由于段的大小不固定（比如一段 $30\text{ KB}$，一段 $15\text{ KB}$），段的装入与撤销又会带来我们熟悉的**外部碎片**；但它在段内分配是精准的，因此**没有页内碎片**。   

### 三、 段表（Segment Table）——段的物理映射记录

为了让 CPU 找到每个段在物理内存中的具体位置，系统为每个进程建立一张**段表**。   

| **段号（隐含为行标）** | **段长（Limit）** | **物理基址（Base）** |
| ---------------------- | ----------------- | -------------------- |
| 0                      | 30 KB             | 40 KB                |
| 1                      | 20 KB             | 80 KB                |
| 2                      | 15 KB             | 120 KB               |
| 3                      | 10 KB             | 150 KB               |

#### 关键区别（对比页表项）：

- **页表项**只需要记录一个数据：**物理块号**（因为页长系统统一固定，不需要记长度）。   
- **段表项**必须同时记录两个核心数据：**段长（Limit）** 和 **物理基址（Base）**（因为每个段的长短不一、基地址各不相同）！   

### 四、 地址变换机构与“两次越界检查”（核心高频考点）

当 CPU 拿到一个逻辑地址 `[段号 S, 段内偏移 W]` 时，硬件地址变换机构的执行步骤如下：   

Plaintext

```
CPU 产生逻辑地址 [段号 S, 段内偏移 W]
               │
               ├───► 【第一次越界检查】: 段号 S >= 段表长度 M ?
               │           │
               │           ├─► [是] 抛出硬件中断: 【段号越界】!
               │           │
               │           └─► [否] (段号合法)
               ▼
   根据段表始址 F 找到该段表项: 表项地址 = F + S * 表项大小
               │
               ▼
   读出该段表项中的 [段长 Limit] 与 [物理基址 Base]
               │
               ├───► 【第二次越界检查】: 段内偏移 W >= 段长 Limit ?
               │           │
               │           ├─► [是] 抛出硬件中断: 【段内地址越界】!
               │           │
               │           └─► [否] (段内偏移合法)
               ▼
   计算物理地址: Physical Address = Base + W
               │
               ▼
   访存存取目标数据/指令 (同样需 2 次访存)
```

> 高频考点剖析：为什么分段系统必须检查两次越界，而分页系统只需一次？   
>
> - **分页系统**：页面大小由地址结构固定（例如 12 位就是 $4\text{ KB}$），低 12 位无论怎么变化，硬件引脚都永远翻不出 $0 \sim 4095$ 的范围，因此**绝不可能发生页内偏移越界**，硬件只需要检查“页号是否超出页表长度”这一项。   
> - **分段系统**：
>   1. **第 1 次检查**：检查段号 $S$ 是否小于段表长度（防止访问不存在的段）；   
>   2. **第 2 次检查**：因为每个段的长短完全不同（有的段只有 90B，有的段有 500B），段内偏移量位数通常按照最大允许段长来预留（如 16 位可表示 64KB）。如果一个只有 90B 的段，程序却试图去读偏移量为 120B 的位置，就必须通过**第 2 次硬件检查（$W \ge \text{Limit}$）**将其拦截并抛出越界中断！   

### 五、 课件经典例题实战解析

> **课件题目**：某段式存储管理系统中，段表如下所示：   
>
> | **段号** | **内存起始地址（Base）** | **段长（Limit）** |
> | -------- | ------------------------ | ----------------- |
> | 0        | 210                      | 500               |
> | 1        | 2350                     | 20                |
> | 2        | 100                      | 90                |
> | 3        | 1350                     | 590               |
> | 4        | 1938                     | 95                |
>
> 试求逻辑地址 **[0, 430]** 和 **[2, 120]** 对应的物理地址。   

- **分析与计算过程**：
  1. **针对逻辑地址 [0, 430]**（段号 $S=0$，段内偏移 $W=430$）：   
     - 检查段号：$S=0 < 5$（段表总长度为 5），段号合法；   
     - 查段表：0 号段的基址为 210，段长为 500；   
     - 检查段内偏移：$W = 430 < \text{段长 } 500$，偏移量合法，未发生越界；   
     - 计算物理地址：$\text{物理地址} = \text{Base} + W = 210 + 430 = \mathbf{640}$。   
  2. **针对逻辑地址 [2, 120]**（段号 $S=2$，段内偏移 $W=120$）：   
     - 检查段号：$S=2 < 5$，段号合法；   
     - 查段表：2 号段的基址为 100，**段长为 90**；   
     - 检查段内偏移：$W = 120 > \text{段长 } 90$，**段内偏移越界**！   
     - 硬件立即触发**越界中断异常**，拒绝访问，不产生物理地址。   

### 本讲回顾与自测小思考

- **分段的本质**：按用户逻辑模块切分，段长不固定，二维逻辑地址，消除内部碎片，但产生外部碎片。   
- **段表项的双字段**：[Limit, Base]，两者缺一不可。   
- **硬件防护机制**：严格执行两次越界检查（先比段表长度，再比段长）。
