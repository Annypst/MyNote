### 一、 为什么必须走向“离散分配”？

在前面的动态分区分配中，操作系统要求把作业存放在**连续的物理内存空间**中。这不可避免地带来了一个矛盾：   

- **连续分配的痛点**：随着进程的频繁装入与撤销，内存中不可避免地散落着大量微小的**外部碎片**。   
- **传统紧凑的代价**：要想利用这些外部碎片，只能使用拼接/紧凑技术，将正在运行的进程在物理内存中大规模搬迁，不仅消耗大量 CPU 和总线资源，还需要暂停进程执行，代价极高。   

为了彻底打破“物理上必须连续”的束缚，操作系统引入了**离散分配方式**：**允许将一个作业或进程分散存放到多个互不相邻的物理内存分区中**。 根据离散分配的基本单位不同，衍生出三种核心方案：   

1. **分页式存储管理**：离散分配的基本单位是固定大小的“页”。   
2. **分段式存储管理**：离散分配的基本单位是具有逻辑意义的“段”。   
3. **段页式存储管理**：融合两者优势，基本单位是段和页。   

### 二、 基本分页存储管理的基本思想

如果一个系统不具备页面对换功能，不支持虚拟存储器，在作业调度运行时必须将其**所有页面一次性全部调入内存，且在运行过程中一直驻留内存**，这种方式被称为**纯分页**或**基本分页存储管理方式**。   

#### 1. 空间的“等长双向切分”

分页管理的核心技巧在于将“虚拟世界”和“现实世界”按照相同的尺度切成网格：   

- **进程逻辑地址空间（虚页）**：把用户进程的逻辑地址空间切成若干个大小相等的区域，称为**页**或**页面（Page）**，从 0 开始依次编号（0号页、1号页、2号页……）。   
- **物理内存空间（实页/页框）**：把物理内存也划分成若干个与页面大小严格相等的区域，称为**物理块**、**存储块**或**页框（Frame）**，同样从 0 开始编号（0号块、1号块……）。   

#### 2. 内存分配方式与页内碎片

- **离散装载**：系统以“物理块”为最小单位给进程分配空间。进程中的各个页面可以被装入到内存中**任意不相邻的物理块**中。   
- **消除外部碎片**：因为内存是按固定大小的块统一划拨的，所有的空闲块都能被任意页面填满，因此**分页系统彻底消除了外部碎片**。   
- **产生页内碎片（内部碎片）**：用户作业的总体积通常不可能恰好等于页面大小的整数倍，**作业的最后一页往往装不满一整块**，导致该块内部留有未被利用的空隙，这被称为**页内碎片**（属于内部碎片的一种）。   

> **课件经典案例**：作业大小为 $9\text{ KB}$，系统页面大小为 $2\text{ KB}$。该作业会被切分为 5 个页面。前 4 个页面装满 $8\text{ KB}$，最后一页（第 4 页）仅有 $1\text{ KB}$，分配一个整块后，就产生了 $1\text{ KB}$ 的页内碎片。   

### 三、 分页系统的逻辑地址结构

在页式存储管理中，任何一个逻辑地址在结构上都可以拆解为两个部分：**页号（Page Number, P）** 与 **页内位移量 / 页内地址（Offset, d 或 W）**。   

Plaintext

```
 31                            12 11                             0
┌────────────────────────────────┬────────────────────────────────┐
│          页号 P                │        页内位移量 d / W        │
└────────────────────────────────┴────────────────────────────────┘
```

#### 1. 位数与容量的换算关系

- **页内位移量的位数决定了页面大小**：若低 $k$ 位表示页内地址，则页面大小为 $L = 2^k$ 字节。   
- **页号的位数决定了进程最多能拥有多少页**：若剩余的高 $m$ 位表示页号，则该逻辑地址空间最多支持 $2^m$ 个页面。   
- **课件示例**：在 32 位逻辑地址系统中，低 0~11 位（共 12 位）为页内地址，则每页大小为 $2^{12}\text{ B} = 4\text{ KB}$；高 12~31 位（共 20 位）为页号，地址空间最多允许拥有 $2^{20} = 1\text{ M}$ 个页面。   

#### 2. 页面大小的权衡机制

页面大小通常为 2 的整数次幂，在实际操作系统中一般处于 $512\text{ B} \sim 8\text{ KB}$ 之间，它的选取是一场精密的工程折中：   

- **若页面偏小**：最后一页浪费的空间更小，减少了页内碎片，能显著提高内存利用率；但每个进程拥有的页数大幅增加，导致记录映射关系的**页表过长**，占用更多宝贵的内存空间，同时调页的 I/O 次数也会增加。   
- **若页面偏大**：进程页数减少，页表紧凑省空间，页面换入换出速度更快；但页内碎片会成倍增加，降低内存利用率。   

### 本讲回顾与自测小思考

- **连续与离散的本质区别**：连续分配需要物理上一大片空闲，离散分配把程序“碎纸化”后装进各个空闲格子里。   
- **碎片的转移**：连续分配头疼的是**外部碎片**（分区间的小残渣）；而分页管理彻底干掉了外部碎片，但由于最后一块填不满，引入了**页内碎片**。   

**小思考：**

1. 为什么操作系统必须把页面大小固定设计为 **2 的整数次幂**（比如 $1\text{ KB}$、$2\text{ KB}$、$4\text{ KB}$），而不是诸如 $1000\text{ B}$ 或 $3000\text{ B}$ 这类更规整的十进制数？（提示：从计算机底层的二进制地址提取与硬件计算效率来考虑）
2. 假定某系统页面大小为 $1\text{ KB}$（即 $1024\text{ B}$），用户作业给出一个十进制逻辑地址为 $1027$，请问它对应的**页号**和**页内位移量**分别是多少？   

针对第一讲的两个自测思考，具体的硬件运行逻辑与独立演算步骤如下：

### 一、 第一问：为什么页面大小必须是 2 的整数次幂？

你直觉抓住了“二进制位运算效率高”的核心，在操作系统与底层 MMU（内存管理单元）的实际硬件实现中，其优势主要体现在**免除算术除法**与**纯硬件引脚拼接**：

1. **避免高开销的除法器与取模运算**：

   - 如果页面大小不是 2 的整数次幂（如 $1000\text{ B}$），CPU 每次取指或读写内存时，硬件都必须执行除法和求模电路：

     $$\text{页号 } P = \lfloor A / 1000 \rfloor, \quad \text{页内偏移 } d = A \pmod{1000}$$

   - 整数除法与取模在硬件上需要消耗数十个时钟周期，若每条指令寻址都要执行一次，CPU 性能将产生严重瓶颈。

2. **硬件总线物理分流（零延迟拆分）**：

   - 当页面大小为 $L = 2^k$ 时：

     $$\text{页号 } P = A \gg k, \quad \text{页内偏移 } d = A \ \& \ (2^k - 1)$$

   - 在电路层面，这根本不需要经过算术逻辑单元（ALU）计算，**只需把地址总线的引脚直接分流**：低 $k$ 根导线作为页内偏移直通物理地址总线，高位导线送入页表查询部件。   

3. **物理地址的纯拼装**：

   - 查出物理块号 $b$ 后，物理地址就是 $b \times 2^k + d$，在硬件上直接把“块号”与“偏移量”的二进制引脚并排拼在一起即可，耗时为 0。   

### 二、 第二问：逻辑地址 1027 的页号与页内位移独立核算

我们来对给定的参数进行独立的数学除法与二进制切片推导：

- **已知条件**：
  - 页面大小 $L = 1\text{ KB} = 1024\text{ B} = 2^{10}\text{ B}$   
  - 逻辑地址 $A = 1027$（十进制）   

#### 1. 十进制除法与取模算法

- **页号（商）**：

  $$P = \lfloor A / L \rfloor = \lfloor 1027 / 1024 \rfloor = 1$$

- **页内位移（余数）**：

  $$d = A \pmod L = 1027 - (1 \times 1024) = 3$$

#### 2. 二进制位切片法

- 页内地址位数 $k = \log_2(1024) = 10$ 位。   

- 将十进制地址 $1027$ 转化为二进制（以 16 位展示）：

  $$1027_{10} = 1024 + 2 + 1 = 0000\ 0100\ 0000\ 0011_2$$

- 按照高位页号、低 10 位偏移进行物理拆分：

  Plaintext

  ```
  逻辑地址: 000001 0000000011
  高位部分（页号 P）: 000001_2 = 1
  低10位（偏移量 d）: 0000000011_2 = 3
  ```

你的分析中推导出偏移量占低 10 位是完全正确的，但计算结果中**把“页号”和“偏移量”的数值搞颠倒了**：得到的余数 $3$ 是**页内位移量**，商 $1$ 才是**页号**。   

接下来正式切入**第二讲：页表机制与基本地址变换机构**。   

### 一、 页表（Page Table）—— 虚实空间的“户口本”

在纯分页系统中，作业被切成多个页离散装入物理内存，逻辑上连续的第 0、1、2 页，在物理内存中可能分别落在 2 号、7 号、1 号物理块。为了找回这些映射关系，操作系统必须为每个进程建立一张表格，称为**页表**。   

Plaintext

```
  逻辑页号 (Page)       物理块号 (Frame)
┌──────────────────┬──────────────────┐
│      0 号页      │      2 号块      │
├──────────────────┼──────────────────┤
│      1 号页      │      3 号块      │
├──────────────────┼──────────────────┤
│      2 号页      │      1 号块      │
├──────────────────┼──────────────────┤
│      3 号页      │      6 号块      │
└──────────────────┴──────────────────┘
```

#### 1. 页表的核心属性

- **存放位置**：页表作为系统管理进程的重要数据结构，通常**常驻在物理内存中**。   

- **页表项（PTE, Page Table Entry）**：页表中的每一行记录被称为一个页表项。在基本分页中，页表项的核心字段就是**物理块号**。   

  > **注意**：页表项里通常**不需要显式存储“页号”**！因为页表在内存中是连续存放的数组结构，页号其实就是数组下标，已知页表首地址，第 $i$ 项的地址就是 $\text{始址} + i \times \text{表项大小}$。   

- **硬件控制寄存器——页表寄存器（PTR, Page Table Register）**：   

  - 当进程未执行时，该进程页表的**物理始址**和页表长度（即页表包含的总页数）存放在其进程控制块（PCB）中；   
  - 当进程被调度上 CPU 运行时，操作系统会将这两项数据加载到 CPU 的专用寄存器 **PTR** 中，供硬件翻译逻辑地址使用。   

#### 2. 基本分页机制的致命弱点：访存次数翻倍

在没有辅助硬件加速的基本分页系统中，CPU 要想读取或写入一个逻辑地址的数据，必须经历**两次访存**：   

1. **第一次访存**：CPU 访问内存中的**页表**，根据逻辑页号查出对应的物理块号；   
2. **第二次访存**：根据计算得到的物理地址，**真正访问内存中的目标指令或数据单元**。   

- **代价**：计算机的执行性能直接下降接近 $50\%$。这也直接催生了我们下一讲要学习的“快表（TLB）”硬件加速机制。   

### 二、 基本地址变换机构（硬件映射流程）

地址变换机构是集成在 CPU 内存管理硬件中的自动化部件，它的核心职责是将用户作业的逻辑地址（$P, d$）自动转化为物理地址（$b, d$）。   

Plaintext

```
CPU 发出逻辑地址 (页号 P, 页内偏移 d)
             │
             ├───► [页号 P] 与 [页表寄存器 PTR 中的页表长度 M] 比较
             │          │
             │          ├─► P >= M : 触发硬件异常【越界中断】!
             │          │
             │          └─► P < M (合法) ──┐
             │                             ▼
             │       根据 PTR 中的页表始址 F，计算目标页表项地址:
             │                   Address = F + P * 表项大小
             │                             │
             │                             ▼
             │                  [第一次访存: 读取页表]
             │                             │
             │                             ▼
             │                     读出物理块号 b
             │                             │
             └─────────────┬───────────────┘
                           │ 
                           ▼
           物理地址拼接: 物理地址 = b * L + d
                           │
                           ▼
                 [第二次访存: 读写目标数据]
```

#### 地址变换全流程拆解：

1. **越界校验**：CPU 捕获逻辑地址，提取出页号 $P$，将 $P$ 与 PTR 寄存器中的**页表长度 $M$** 进行硬件比对。   
   - **若 $P \ge M$**：说明该进程试图访问超过其分配范围的页面，硬件立即触发**越界中断**（属于内部异常）。   
2. **寻址页表项**：若未越界，硬件用页表起始地址 $F$ 加上 $P \times \text{每个页表项占用的字节数}$，得到当前页表项在主存中的绝对物理地址。   
3. **读取物理块号**：CPU 发起第 1 次访存，从页表中读取出该页对应的物理块号 $b$。   
4. **拼接物理地址**：将块号 $b$ 与原逻辑地址中的页内位移 $d$ 组合（或执行 $b \times L + d$），形成真实的物理地址。   
5. **执行数据存取**：CPU 发起第 2 次访存，执行真正的指令取指或数据读写。   

### 三、 经典地址换算实战解析

#### 【例题 1：位宽与容量换算】

> **题目**：某分页存储管理系统，逻辑地址空间最大为 16 页，每页 $2048\text{ B}$，物理内存共有 8 个存储块。试求：逻辑地址至少为多少位？物理地址至少为多少位？物理内存总容量多大？   

- **推导过程**：
  1. 每页大小 $L = 2048\text{ B} = 2^{11}\text{ B}$，因此页内地址（位移量 $d$）占 **11 位**。   
  2. 逻辑空间最多 16 页，即 $16 = 2^4$ 页，因此页号 $P$ 占 **4 位**。   
     - **逻辑地址总长度** $= 4\text{ 位 (页号)} + 11\text{ 位 (位移)} = \mathbf{15\text{ 位}}$。   
  3. 内存块大小与页面大小严格一致，因此块内位移也是 **11 位**。   
  4. 物理内存共 8 个块，即 $8 = 2^3$ 块，因此物理块号 $b$ 占 **3 位**。   
     - **物理地址总长度** $= 3\text{ 位 (块号)} + 11\text{ 位 (块内位移)} = \mathbf{14\text{ 位}}$。   
     - **物理内存总容量** $= 2^{14}\text{ B} = 16\text{ KB}$（或 $8 \times 2048\text{ B} = 16\text{ KB}$）。   

#### 【例题 2：实际地址动态映射】

> **题目**：某分页系统，页面大小为 $1024\text{ B}$，页表如下所示，页表长度为 4（页号范围为 0~3）：   
>
> | **页号** | **物理块号** |
> | -------- | ------------ |
> | 0        | 2            |
> | 1        | 3            |
> | 2        | 1            |
> | 3        | 6            |
>
> 试求十进制逻辑地址 **1011**、**2148** 以及 **5012** 对应的物理地址。   

- **推导过程**：
  - 页面大小 $L = 1024\text{ B}$。   
  - **针对逻辑地址 1011**：   
    - 页号 $P = \lfloor 1011 / 1024 \rfloor = 0$，页内位移 $d = 1011 \pmod{1024} = 1011$。   
    - 页号 $0 < 4$，未越界。查页表，0 号页映射到 **2 号物理块**。   
    - 物理地址 $= 2 \times 1024 + 1011 = 2048 + 1011 = \mathbf{3059}$。 (注：课件上写成十六进制：$1011_{10} = \text{0x03F3}$，块号 2 对应 $\text{0x0800}$，相加得 $\text{0x0BF3H} = 3059_{10}$，两者完全等价)。   
  - **针对逻辑地址 2148**：   
    - 页号 $P = \lfloor 2148 / 1024 \rfloor = 2$，页内位移 $d = 2148 \pmod{1024} = 100$。
    - 页号 $2 < 4$，未越界。查页表，2 号页映射到 **1 号物理块**。   
    - 物理地址 $= 1 \times 1024 + 100 = \mathbf{1124}$。
  - **针对逻辑地址 5012**：   
    - 页号 $P = \lfloor 5012 / 1024 \rfloor = 4$，页内位移 $d = 5012 \pmod{1024} = 916$。   
    - 页号 $P = 4 \ge \text{页表长度 } 4$，**地址越界**，硬件抛出**越界中断异常**，拒绝访问。   

### 本讲回顾与自测小思考

- **页表项不需要存页号**：利用数组下标寻址，表项里存的是物理块号。   
- **基本分页访存效率**：读一个字需访存 2 次（先查页表，再读数据）。   
- **越界判断的标准**：页号是否超出页表长度（$P \ge M$ 触发异常）。   

**小思考：** 假设某分页系统页面大小为 $4\text{ KB}$，页表项大小为 $4\text{ B}$。若某个进程的页表在内存中从物理地址 `0x00100000` 处开始存放。

1. 当 CPU 需要翻译逻辑地址 `0x00003ABC` 时，请问页号 $P$ 和页内偏移量 $d$ 分别是多少（十六进制表示）？
2. 硬件在第一次访存去查页表时，读取的那个页表项在内存中的**物理起始地址**是多少？

请写出你的推导步骤，或者准备好推进到**第三讲：具有快表（TLB）的地址变换机构与有效访存时间（EAT）计算**时，回复 **“继续”**！

这种误解在刚接触地址结构时非常普遍，把“位宽（Bit Width，占几位）”和“字段数值（Value，具体是几）”弄混是很多初学者都会踩的坑。   

现在你已经把这条脉络完全理清了：

1. **位宽层面**：页面大小为 $1\text{ KB} = 2^{10}\text{ B}$，因此低位**固定切出 10 个比特位**作为页内偏移量；   
2. **数值层面**：十进制逻辑地址 1027 换成二进制后，低 10 位包含的数值恰好是 3，高位剩下的数值是 1（即 1 号页、偏移 3）。   

搞清楚了这个对应关系，面对实际考试和工程中最常见的**十六进制地址**时，就完全不需要做任何十进制除法，直接用“二进制/十六进制直读法”即可。   

我们顺着这个思路，把上一讲留下的十六进制小练习快速过一遍，看看你能不能一秒看出答案：

> **已知条件**：
>
> - 页面大小为 $4\text{ KB}$（即 $4096\text{ B} = 2^{12}\text{ B}$）   
> - 页表项大小为 $4\text{ B}$
> - 进程页表在物理内存中的起始地址为 `0x00100000`   
> - CPU 发出的逻辑地址为 **`0x00003ABC`**

**核心秒杀技巧**：

- 页面大小 $4\text{ KB} = 2^{12}\text{ B}$，意味着页内偏移量占 **12 个二进制位**。   
- 在十六进制中，**每一位数字恰好对应 4 个二进制位**（$16 = 2^4$）。因此 12 位二进制正好对应**末尾的 3 位十六进制数**！
- 拿起剪刀从末尾切下 3 位十六进制数：
  - **页内偏移量 $d$**：直接抓末尾 3 位 $\to$ **`0xABC`**   
  - **页号 $P$**：前面剩下的全部高位 $\to$ **`0x00003`（即 3 号页）**
