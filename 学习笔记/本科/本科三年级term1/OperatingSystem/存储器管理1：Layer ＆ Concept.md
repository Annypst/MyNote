### 一、 存储器的层次结构（Memory Hierarchy）

#### 1. 为什么需要层次结构？

计算机对存储器的理想追求永远是：**速度极快、容量极大、价格极低**。但这三者在物理规律上存在天然的矛盾：

- 速度越快，集成度要求越高，成本越昂贵，容量做不大；
- 价格越便宜、容量越大的介质，访问速度越慢。

为了化解 **“CPU 极快的计算速度”** 与 **“廉价外存极慢的存取速度”** 之间的巨大鸿沟，现代计算机系统设计了**金字塔式的分层存储结构**。

Plaintext

```
               ▲
              / \           【CPU 内部】 寄存器 (Registers)        速度最快、容量最小、造价最高
             /   \
            / Cache\        【高速缓存】 L1 / L2 / L3 Cache       弥补 CPU 与内存的速度差
           /---------\
          /   主存    \     【主存储器】 内存 (RAM)                CPU 能直接寻址访问的运行空间
         /-------------\
        /     辅存      \   【辅助存储器】固态硬盘(SSD) / 机械硬盘(HDD)  容量极大、断电不丢失、CPU不可直接寻址
       /                 \
      ---------------------
```

#### 2. 各层次的定位与特点

从金字塔顶端到底端，呈现出 **速度递减、容量递增、单位成本递减** 的规律：

1. **寄存器（Registers）**：位于 CPU 内部，访问延迟在纳秒（时钟周期）级，容量通常只有几 KB。用于保存当前正在执行的指令、运算操作数和状态标志。
2. **高速缓存（Cache）**：同样位于 CPU 芯片内/旁，基于局部性原理，缓存内存中最常访问的数据块，以减少 CPU 对内存的直接访问次数。
3. **主存储器（Main Memory，即内存/主存）**：由半导体存储器（RAM）构成。**CPU 能够通过总线直接寻址访问的极限范围就到主存为止**。程序只有被加载进主存，CPU 才能执行其指令。缺点是断电后数据易失。
4. **辅助存储器（Secondary Storage，即外存/辅存）**：如磁盘、SSD 等。断电后数据仍能长期保存，容量很大，但 CPU 不能直接对辅存进行读写，必须先将数据成块调入主存。

> **核心划分**：
>
> 寄存器、Cache 和主存合称为**系统内部存储（内存）**；辅存称为**外部存储（外存）**。
>
> 操作系统存储管理主要聚焦在**主存的利用、分配**，以及**主存与辅存之间的数据调度**。

### 二、 存储器管理的概念与核心目标

#### 1. 什么是存储器管理？

在单道程序系统中，内存中一次只跑一个程序，管理非常简单。但在现代**多道程序并发系统**中，内存中同时驻留着几十甚至几百个进程的代码与数据。

**存储器管理（Memory Management）**，本质上就是操作系统的内存管理模块（协同硬件体系）对主存储器空间进行**规划、分配、监控、保护以及扩充**的一套软硬件协同机制。

#### 2. 存储器管理的四大核心目标（功能）

操作系统管理内存，主要解决以下四个问题：

1. **内存空间的分配与回收（Allocation & Deallocation）**
   - 记录哪些内存已被占用、哪些处于空闲；
   - 当进程创建或申请内存时，按一定算法划拨空间；进程结束时，及时收回并整合内存碎片。
2. **地址变换（Address Translation）**
   - 程序员写代码、编译生成的地址通常是“相对的逻辑地址”，而内存条上的单元是“绝对的物理地址”。
   - 操作系统必须提供某种机制，在程序执行时将**逻辑地址动态映射转换为物理地址**（这也是我们后续要讲的基地址、重定位的核心）。
3. **内存保护与共享（Protection & Sharing）**
   - **保护（隔离）**：各进程在各自合法区域内运行，严禁非法越界读写其他进程或操作系统内核的内存空间。
   - **共享**：在确保安全的前提下，允许多个进程访问同一块物理内存（例如多个进程共享同一个标准 C 库函数代码、或进程间共享内存通信）。
4. **内存扩充（Virtual Memory，虚拟存储）**
   - 物理内存往往不够大（比如只有 16GB 物理内存，却要跑 30GB 的游戏或多个大型应用）。
   - 操作系统利用主存与外存的层次关系，从逻辑上把内存空间“放大”，实现**虚拟存储**，让用户感觉自己拥有的内存空间远大于实际物理容量。

### 本讲回顾与自测小思考

- **层次结构记忆口诀**：顶小快贵（寄存器/Cache），底大慢廉（外存），中枢在内存。
- **管理的本质**：让多道程序既能“安全隔离”又能“高效率共享”，把有限的物理内存用出“无限虚拟空间”的效果。

**小思考：**

> 为什么 CPU 执行指令时可以直接读取内存中的数据，却**不能直接执行**存放在固态硬盘（SSD）里的程序指令代码？

1. **速度悬殊（性能原因）**：内存访问延迟在几十纳秒（ns）级，而固态硬盘（即使是极快的高速 NVMe SSD）也在几十微秒（$\mu s$）级，相差成百上千倍。如果让 CPU 直接在 SSD 上取指执行，CPU 的运算核心每跑一步都要停顿成千上万个时钟周期，整机性能将直接崩溃。
2. **硬件寻址方式的根本冲突（底层致命原因）**：
   - CPU 的取指译码机构要求存储介质必须支持**按字节随机寻址（Byte-Addressable）**，CPU 发出一个具体地址，就能通过系统总线瞬间抓取指定内存单元的指令或数据；
   - SSD/机械硬盘在硬件电气结构上属于**块设备（Block Device）**，只能以“扇区/数据块（如 4KB）”为最小单位成片读写，CPU 无法下达指令去直接读写硬盘内部偏移第 5 个字节的内容。因此必须由操作系统通过 I/O 中断和 DMA，成块搬入内存后供 CPU 运行。

理清了主存与外存的界限后，我们正式切入**第二讲：名空间（Name Space）与 逻辑（虚拟）地址**。

这两个概念是理解“程序是如何从写出来的代码变成能在机器里跑起来的实体”的关键起点。

### 一、 名空间（Name Space / 符号名空间）

#### 1. 概念定义

在写代码时，程序员并不知道、也不需要关心程序将来会被加载到内存的哪个具体位置。我们使用的是具象化的标识符：

- 变量名：`int counter = 0;`、`float total_price;`
- 函数名与标号：`void print_report() { ... }`、`goto loop_start;`

这种**由程序员在高级语言源程序中使用的、以符号和变量名命名的标识符集合**，就称为**名空间（Name Space）**，或**符号名空间**。

#### 2. 名空间的特点

- **面向人类设计**：名空间是人类思维与计算机底层硬件之间的缓冲，提供高可读性与抽象性。
- **CPU 无法直接识别**：CPU 电路只认电信号和二进制数字地址，根本无法理解什么是 `counter` 或 `loop_start`。因此，名空间必须经过翻译转化。

### 二、 逻辑地址（Logical Address）与逻辑地址空间

#### 1. 概念定义

通过编译程序（Compiler）和汇编程序将源程序翻译成目标模块后，源程序名空间中的符号名被替换成了**数字地址**。

这个数字地址并不是物理内存条上的真实位置，而是**从 0 开始编址的相对地址**，我们称之为**逻辑地址（Logical Address）**，在许多教材和体系结构中也称为**相对地址**或**虚拟地址（Virtual Address）**。

- **逻辑地址空间**：一个目标模块或一个完整程序所占用的所有逻辑地址的集合。对于一个 32 位系统，每个进程的理论逻辑地址空间可以达到 $2^{32} = 4\text{GB}$（从 `0x00000000` 到 `0xFFFFFFFF`）。

#### 2. 为什么必须引入“从 0 开始”的逻辑地址？

如果让编译程序直接生成物理地址：

- 程序员写代码时必须提前预测：“我的程序将来要放在物理内存的 1000M 还是 2000M 位置？”
- 一旦物理位置被别的程序占用，程序就无法加载运行。

引入逻辑地址，实现了**程序编制与物理存储的彻底解耦**：

> 编译器把每个程序都当作“全世界只有它自己”，统一规定：**程序的第 1 行代码就是逻辑地址 0，第 2 行代码是逻辑地址 4……** 这样无论程序将来被搬到物理内存的哪个角落，其内部的相对偏移关系是恒定不变的。

### 三、 从“名空间”到“逻辑地址”的演变过程

一个源程序要变成可在系统中调度执行的实体，在地址形态上通常经历三个阶段：

Plaintext

```
【源程序】                【目标模块】                   【装入模块】
 (C/C++ 代码)              (编译后 .obj)                 (链接后 .exe)
 
 int counter;            offset: 0x0020                逻辑地址: 0x0020
 goto loop;   =======>   JMP 0x0100       =======>     JMP 0x0500 (多模块合并重排)
 
 [名空间 / 符号]          [各自独立的相对地址]            [统一且连续的逻辑地址空间]
```

1. **编译阶段（名空间 $\to$ 相对地址）**：编译程序将每个源文件中的变量名、标号翻译成各自以 0 为起点的相对地址。
2. **链接阶段（多目标模块拼接）**：链接程序（Linker）将各个目标模块以及所需要的库函数拼接在一起，解决模块间的外部引用，形成一个**拥有全局统一逻辑地址编址的完整装入模块（装入空间）**。

### 本讲核心提炼

- **名空间**：程序员眼中的世界，满是 `x, y, func()` 这样的符号。
- **逻辑地址**：编译器和链接器构建的虚拟世界，从 `0` 开始编址，代表数据和代码在程序内部的**相对位移量**。

### 一、 物理地址与物理地址空间

#### 1. 概念定义

- **物理地址（Physical Address，又称绝对地址）**：这是**主存条内部各存储单元真实的、物理的硬件地址**。当 CPU 真正发起读写总线周期时，总线上传递的电信号地址就是物理地址。从 0 开始，一直编址到机器物理内存的最大容量（例如 16GB 内存，物理地址范围就是 `0x00000000` 到 `0x3FFFFFFFF`）。
- **物理地址空间**：物理内存中所有物理单元集合构成的地址范围。

### 二、 基地址（Base Address）与重定位寄存器

操作系统为了让互不相干的进程能够安全地共享同一个物理内存，最经典的基础方案就是**基地址划分（连续分配模式下的动态重定位）**：

#### 1. 什么是基地址？

当操作系统决定把一个程序装入物理内存时，会在内存中为它挑选一段连续的空闲区间。 这段空闲空间的**起始物理地址**，就称为该进程的**基地址（Base Address）**。

#### 2. 基地址寄存器（Base Register，又称重定位寄存器）

CPU 的硬件体系结构中专门提供了一个寄存器来存放当前运行进程的基地址：

- 当操作系统调度切换到**微信**运行时，将微信在物理内存的起始地址（比如 `10000`）写入该寄存器；
- 当切换到**播放器**运行时，操作系统把播放器的起始地址（比如 `50000`）写入该寄存器。

### 三、 地址变换与地址重定位（Relocation）

将程序中的**逻辑地址**转换为内存中的**物理地址**的过程，叫做**地址重定位（Address Relocation）**，主要有两种演进形式：

#### 1. 静态重定位（早期批处理系统）

- **时机**：在程序**装入内存时**一次性完成。
- **做法**：由装入程序（Loader）修改程序内部所有需要重定位的指令和数据地址（比如把所有地址都加上起始物理地址）。
- **弊端**：程序一旦装入内存，在运行期间**物理位置不能再移动**；而且无法在运行时申请更多空间。

#### 2. 动态重定位（现代系统基础）

- **时机**：程序装入内存后，指令中的地址依然保留为逻辑地址，转换推迟到 **CPU 执行该条指令时，由硬件动态完成**。
- **硬件支持——MMU（Memory Management Unit，内存管理单元）**： CPU 内部的 MMU 包含两个关键寄存器：
  1. **基址寄存器（Base Register / 重定位寄存器）**：存放该进程在内存中的起始物理地址。
  2. **限长寄存器（Limit Register / 界地址寄存器）**：存放该进程的逻辑地址空间大小（防止越界）。

#### 转换计算公式：

$$\text{物理地址} = \text{逻辑地址} + \text{基地址}$$

Plaintext

```
CPU 产生逻辑地址 (如 100)
       │
       ▼
 ┌───────────┐    超出范围 (>= 限长)
 │  < 限长?   │ ─────────────────────► 触发硬件异常（越界中断，报 Segmentation Fault）
 └─────┬─────┘
       │ 未越界
       ▼
 ┌───────────┐
 │ + 基地址  │  (若基地址为 10000)
 └─────┬─────┘
       ▼
 物理地址 10100 ────► 访问物理内存条
```

> **回答你刚才的问题**：
>
> 微信的逻辑地址 `100` + 微信的基地址 `10000` $\to$ 访问物理内存 `10100`；
>
> 播放器的逻辑地址 `100` + 播放器的基地址 `50000` $\to$ 访问物理内存 `50100`。
>
> **逻辑地址相同，但基地址不同，最终映射到的物理地址完全独立！**

- CPU 内部包含寄存器，而通过总线可直接按字节寻址的主存（内存）是运行程序的上限边界；SSD 等外存是块设备，CPU 无法直接通过总线按字节寻址。

- 名空间中的符号（变量名、函数名）经过编译器和链接器处理后，统一转变为以 0 为起点的相对地址（即逻辑地址/虚拟地址）。

**第 3 题：正确答案是 A（你的答案是 D）**

- 我们先看逻辑地址与限长的对比：逻辑地址是 `0x00012000`，限长是 `0x00050000`。十六进制下 `12000 < 50000`，并没有越界。

- 既然未越界，MMU 硬件就会执行相加运算：

  $$\text{物理地址} = \text{基地址} + \text{逻辑地址} = \text{0x00200000} + \text{0x00012000} = \text{0x00212000}$$

- 这里选错很可能是因为快速扫视时把位数看岔了，误判为了越界。

**第 4 题：正确答案是 C（你的答案是 D）**

- 此时逻辑地址为 `0x00060000`，显然大于限长 `0x00050000`，确实越界了。
- 限长寄存器是操作系统给进程设立的“硬件安全防火墙”，MMU 发现越界时**绝不能擅自修改硬件寄存器来扩容**，而是立刻向 CPU 汇报越界异常中断，由操作系统终止该进程（报段错误 Segmentation fault）。因此应选 C。

### 二、 简答题点评

- **静态重定位**：在装入内存那一刻，装入程序把指令里所有的目标地址、指针变量全改写成了**绝对物理地址**。如果把程序在内存里整体搬家，代码里写死的绝对地址就会指向原本的旧位置甚至别的进程空间，程序瞬间崩溃。
- **动态重定位**：内存中存放的代码依然全部保持**相对的逻辑地址**。操作系统如果需要把进程挪动位置，只需要把进程内容拷贝到新区域，然后**仅仅修改基址寄存器里的那一个数值**。当 CPU 取指令执行时，MMU 会拿指令里的逻辑地址加上新的基地址，自动完成对新物理地址的寻址。

今天这节课，你已经彻底搞懂了：

1. **存储层次**为什么必须“顶小快贵、底大慢廉”；
2. 程序员的**名空间**是如何演变为**逻辑地址**的；
3. 为什么**基地址与 MMU** 能让逻辑地址相同的程序在物理内存中井水不犯河水；
4. **静态与动态重定位**在硬件支持和进程迁移灵活性上的巨大差异。
