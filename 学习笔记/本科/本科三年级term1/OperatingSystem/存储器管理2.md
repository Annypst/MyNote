### 一、 程序的执行过程：编译、链接、运行装入

从我们敲下一行行代码，到 CPU 真正执行它，必须经过三个核心步骤：

Plaintext

```
【源程序】(.c/.cpp) 
    │
    ▼ (编译阶段 Compiler)
【目标模块】(.obj/.o) ──┐
【库函数】(.lib/.so)   ├──► (链接阶段 Linker)
                        │
                        ▼
                【装入模块】(.exe/可执行文件)
                        │
                        ▼ (装入阶段 Loader)
                【物理内存】(运行态进程)
```

1. **编译（Compile）**
   - **任务**：由编译程序将程序员写的源代码翻译成机器语言构成的**目标模块（Object Module）**。
   - **地址形态**：此时每个目标模块内部使用的是**以 0 为起点的相对逻辑地址**。不同模块（比如 `main.c` 和 `util.c`）内部的地址都是各自分立的 `0, 1, 2...`。
2. **链接（Link）**
   - **任务**：将编译后的一组目标模块，以及它们所需要的库函数接口“粘合”起来，解决各模块之间的**外部符号引用**（比如 `main.o` 调用了 `util.o` 里的函数）。
   - **地址形态**：链接程序将散落的目标模块拼装成一个统一的、全局连续编址的**装入模块（可执行文件）**。
3. **装入（Load）与运行**
   - **任务**：由装入程序（Loader）将磁盘上的可执行文件搬入主存储器（内存），将其逻辑地址映射或变换为物理地址，并为其创建进程控制块（PCB），交由 CPU 调度执行。

### 二、 链接的三种方式（重点：静态链接 vs 运行时动态链接）

链接的本质是**确定函数和变量的相对引用关系**。根据“执行链接的时机”不同，主要分为以下三种：

#### 1. 静态链接（Static Linking）

- **时机**：在程序**运行之前**，链接阶段直接完成。
- **过程**：链接器将所有目标模块以及引用的库代码（如 `.lib` 或 `.a` 静态库）**完整地拷贝一份**，严丝合缝地拼接成一个巨大的、独立的可执行文件（如 `.exe`）。
- **优缺点**：
  - **优点**：运行速度快，独立性强（移到别的电脑上无需依赖外部库文件即可独立运行）。
  - **缺点**：
    1. **极其浪费磁盘与内存**：如果 100 个程序都用到了 C 语言的 `printf` 库，这 100 个可执行文件里各自都塞了一份 `printf` 的机器码；同时运行时，内存中驻留了 100 份相同的代码副本。
    2. **更新与维护极其痛苦**：只要库中有一个小 Bug 修复，所有依赖它的应用程序全部必须**重新编译并重新链接**。

#### 2. 装入时动态链接（Load-time Dynamic Linking）

- **时机**：程序在编译时并不拼装库函数，而是在**装入内存的同时**边装入边链接。
- **过程**：装入程序发现缺少某个模块，就去磁盘找到它一并装入内存并完成地址重定位。

#### 3. 运行时动态链接（Run-time Dynamic Linking）

- **时机**：将链接推迟到**程序执行中具体用到某个模块的那一刻**。
- **过程**：
  - 可执行文件中只保留一个“存根（Stub）”或占位符号。
  - 当程序执行流真正跳转到该外部函数时（例如点击了软件里的“高级打印”功能），系统才会检查该模块（Windows 的 `.dll` 或 Linux 的 `.so`）是否在内存中：
    - 若不在，从磁盘读取并装入内存；
    - 若已经在内存中（被其他进程调入），则直接共享该内存副本。
- **优缺点**：
  - **优点**：
    1. **节省内存与磁盘空间**：不需要的功能模块根本不占内存；多个并发运行的进程可以**共享同一个动态库在物理内存中的物理副本**。
    2. **模块化与热更新方便**：只需替换损坏或升级的 `.dll/.so` 文件，主程序完全无需重新编译链接。
  - **缺点**：首次调用某个模块时会有微小的装入和解析时延。

### 本讲核心对比表

| **特征**          | **静态链接（Static）**               | **运行时动态链接（Run-time Dynamic）** |
| ----------------- | ------------------------------------ | -------------------------------------- |
| **链接完成时机**  | 程序运行前（生成 exe 时）            | 程序运行期间（指令真正调用时）         |
| **库文件依赖**    | 代码已被打入目标文件，运行无外部依赖 | 运行时依赖 `.dll` 或 `.so` 动态链接库  |
| **内存/外存占用** | 大（每个程序都内嵌一套副本）         | 小（多进程共享同一内存副本）           |
| **更新与补丁**    | 牵一发而动全身（需全量重编译发布）   | 模块化热插拔（仅需覆盖升级库文件）     |

### 一、 什么是对换技术（Swapping）？

#### 1. 核心思想

对换技术是指：**在内存紧张时，操作系统把内存中某些暂时不能运行的进程（或其部分代码/数据）调出到外存的对换区（Swap Space）；腾出内存空间后，再把外存中已经具备运行条件的进程调入内存。**

- **换出（Swap-out）**：内存 $\to$ 外存对换区。
- **换入（Swap-in）**：外存对换区 $\to$ 内存。

#### 2. 对换的两种类型

1. **整体对换（中级调度 / 进程对换）**：
   - **单位**：以**整个进程**为单位进行换入换出。
   - **目的**：解决内存整体严重不足的问题，缓解多道程序度的压力。
2. **部分对换（页面/分段对换）**：
   - **单位**：以进程的“页（Page）”**或**“段（Segment）”为单位。
   - **目的**：提供更精细的虚存管理（这就是现代操作系统虚拟内存置换的底层逻辑）。

### 二、 核心考点：挂起（Suspend）与 阻塞（Block）的本质区别

很多同学在考研或期末考中容易把“挂起”和“阻塞”混为一谈。通过对换技术，你可以彻底看清它们的区别：

| **状态类型**              | **核心关注点**         | **进程的代码与数据放在哪里？** | **进程是否在等待某个资源/事件？**                            |
| ------------------------- | ---------------------- | ------------------------------ | ------------------------------------------------------------ |
| **阻塞状态（Blocked）**   | 进程的**运行推进条件** | **在物理内存中**               | **是**（等待 I/O、信号量、锁等）                             |
| **挂起状态（Suspended）** | 进程的**物理驻留位置** | **在外存（对换区）中**         | **不一定**（可以因为缺内存被挂起，也可以因为等待事件被挂起） |

> **关键认知**：
>
> - **阻塞态**：进程还在内存里占着地方，只是 CPU 不给它跑，在排队等数据回来。
> - **挂起态**：操作系统的内存实在装不下了，直接把它**整个人“打包扔到了外存对换区”**，彻底释放了它的内存空间。

因此，现代操作系统引入了**活跃/静止状态划分**：

1. **活动阻塞（Blocked Active）**：在内存中等待事件。
2. **静止阻塞（Blocked Suspended）**：在外存中等待事件（换出）。
3. **活动就绪（Ready Active）**：在内存中等待 CPU 调度。
4. **静止就绪（Ready Suspended）**：在外存中，只要调回内存就能立即运行（换入）。

### 三、 对换空间的管理与磁盘分区

操作系统通常将磁盘（外存）在逻辑上划分为两个完全不同特性的区域：

Plaintext

```
┌───────────────────────────────┬───────────────────────────────┐
│        文件区 (File Area)      │       对换区 (Swap Space)      │
├───────────────────────────────┼───────────────────────────────┤
│ 追求：存储空间的利用率 (省空间) │ 追求：换入换出的极致速度 (要效率)│
│ 分配方式：离散分配 (索引/链接) │ 分配方式：连续分配 (成片连续读写)│
└───────────────────────────────┴───────────────────────────────┘
```

1. **文件区**：
   - 存放用户的长期文件、软件、照片等。
   - 频繁增删改查，目标是**尽量不浪费磁盘空间**，允许离散存放。
2. **对换区**：
   - 专门给对换机制使用的临时缓存区（Windows 下的 `pagefile.sys`，Linux 下的 `Swap` 分区）。
   - 进程换入换出极其频繁，目标是 I/O 速度越快越好，所以通常采用**连续分配方式**，一次成片读写以减少磁盘寻道时间。

### 四、 进程的换入与换出机制

#### 1. 换出谁？（Swap-out 策略）

当内存告急时，操作系统按什么优先级挑选牺牲品扔到外存？

1. **首选**：处于阻塞状态（且短时间内不可能被唤醒）的进程。反正它在内存也是干等着，占着茅坑不拉屎。
2. **次选**：优先级较低的就绪进程。
3. **注意保护**：带有重要系统任务（如内核守护进程）或正在进行直接内存存取（DMA I/O 操作）的进程，**绝对不能被换出**，否则外设直接把数据写到了已经被回收的物理内存上。

#### 2. 换入谁？（Swap-in 策略）

1. 操作系统会定期查看对换区中的“**静止就绪（Ready Suspended）**”进程。
2. 只要内存有空闲，优先挑出**在外存中驻留时间最长**或**优先级最高**的就绪进程调回内存。

### 本讲回顾与小思考

- **对换的本质**：用时间换空间，利用外存连续的对换区当“临时中转站”。
- **挂起 vs 阻塞**：挂起看“内存/外存位置”，阻塞看“CPU运行条件”。

### 一、 “扩充内存容量”的思维演进

在计算机发展的历史长河中，程序员手头的程序体积永远在飞速膨胀，而物理内存条的容量与造价永远受限。操作系统为了解决“小内存运行大程序”或“小内存运行多程序”，经历了三个关键阶段的思维演进：

1. **第一代：覆盖技术（Overlaying）**
   - **特点**：同一程序内部的不同代码段，分时共享同一块内存。
   - **代价**：全靠程序员手工在代码里拆分结构，对人极其不友好。
2. **第二代：对换技术（Swapping）**
   - **特点**：以**进程**为单位换入换出，把外存对换区当作内存的后备缓冲。
   - **局限**：虽然解决了多进程并发时的内存短缺，但**单个进程的总体积依然不能超过物理内存的总上限**。
3. **第三代：虚拟存储技术（Virtual Memory）**
   - **特点**：结合了分页/分段机制，以更小的“页”或“段”为单位按需调入、动态置换，彻底实现了“逻辑上近乎无限的内存空间”。（这是我们下一大章的绝对重头戏）。

### 二、 早期覆盖技术（Overlay）简析

> 覆盖技术主要活跃在 20 世纪六七十年代的 DOS 等早期单道/简单多道批处理系统中。现代由于虚存和分页机制的普及，**覆盖技术已基本退出历史舞台**，在考研与期末考中通常只作为概念背景了解。

#### 1. 核心思想

**把程序划分为若干个功能相对独立的程序段，按照它们之间的调用先后关系，让那些不会同时执行的程序段，分时共享同一块物理内存空间。**

- **常驻区（Fixed Area）**：存放程序中自始至终都需要用到的核心代码（如主函数 `main()`、常用的全局变量），这部分一旦装入内存就常驻不退。
- **覆盖区（Overlay Area）**：根据不会同时运行的模块的最大体积，开辟一块共享内存区。需要执行模块 B 时把 B 调入；执行到模块 C 时，直接把模块 C 调入覆盖原先 B 的位置。

#### 2. 经典模型图解

假设一个程序结构如下：

- 主模块 $A$（10KB）：随时需要调用 $B$ 或 $C$；
- 模块 $B$（20KB）与模块 $C$（30KB）**互不调用**；
- 模块 $B$ 执行时会调用 $D$（15KB）；模块 $C$ 执行时会调用 $E$（20KB）与 $F$（10KB）。

Plaintext

```
               ┌── 模块 B (20KB) ─── 模块 D (15KB)
模块 A (10KB) ─┤
               └── 模块 C (30KB) ──┬── 模块 E (20KB)
                                   └── 模块 F (10KB)
```

- **若不采用覆盖技术**：全部装入内存需要：$10 + 20 + 15 + 30 + 20 + 10 = 105\text{ KB}$。
- **若采用覆盖技术**：
  - **常驻区**：放置模块 $A$（10 KB）。
  - **覆盖区 1**（容纳 $B$ 或 $C$）：大小取 $\max(B, C) = \max(20, 30) = 30\text{ KB}$。
  - **覆盖区 2**（容纳 $D$ 或 $E$ 或 $F$）：大小取 $\max(D, E, F) = \max(15, 20, 10) = 20\text{ KB}$。
  - **所需内存总和**：$10 + 30 + 20 = 60\text{ KB}$（比原来省了将近一半的内存！）。

#### 3. 为什么覆盖技术会被淘汰？

- **对程序员极其残忍**：操作系统自己不知道哪些模块互斥、何时调用，必须由**程序员人工把控程序的调用树结构**，并亲手编写覆盖描述文件。
- **破坏模块化与可维护性**：程序一旦变大变复杂，函数调用关系错综复杂，人工设计覆盖树几乎不可能完成。

### 三、 对换技术 vs 覆盖技术（核心考点速查）

| **对比维度**         | **覆盖技术（Overlay）**                  | **对换技术（Swapping）**             |
| -------------------- | ---------------------------------------- | ------------------------------------ |
| **发生范围**         | 运行在**同一个进程/程序内部**            | 发生在**不同进程（或进程间）**之间   |
| **对程序员的透明性** | **不透明**（必须程序员人工拆分设计结构） | **完全透明**（全由操作系统内核控制） |
| **主要目标**         | 解决“**单程序体积大于内存**”的问题       | 缓解“**并发多进程争抢内存**”的冲突   |
| **所处时代**         | 早期单道/小型系统（已基本淘汰）          | 现代操作系统通用后台支撑             |

### 一、 单项选择题

#### 1. 链接方式对比
