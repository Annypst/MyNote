## 进程与线程

进程与线程的本质区别在于：**进程是操作系统进行资源分配和保护的基本单位，而线程是 CPU 调度和执行的基本单位。**

在早期单线程操作系统中，这两个概念是重合的；现代操作系统为了提高并发性能，将“资源拥有”与“CPU 调度”这两个职责彻底解耦，分离出了进程与线程。

### 1. 直观比喻：工厂车间与流水线工人

- **进程（Process）相当于一个独立的工厂车间**：
  - 拥有自己独立圈定的土地、厂房、设备、原料仓和工具箱（即独立的虚拟内存空间、堆、打开的文件句柄、环境变量等）。
  - 两个车间之间有高墙阻隔，互不干扰，一个车间发生爆炸通常不会直接摧毁另一个车间。
- **线程（Thread）相当于车间里的工人**：
  - 一个车间内可以雇佣多名工人并发干活。
  - 所有工人**共享**这个车间里的厂房、设备和材料（共享进程的代码段、数据段、堆和系统资源）。
  - 每个工人只需要自带随身的小记事本和操作手套（拥有自己私有的程序计数器 PC、一组通用寄存器和独立的执行栈）。

### 2. 核心技术维度的深度对比

#### ① 资源拥有与地址空间

- **进程**：拥有完全独立的虚拟地址空间。操作系统为每个进程维护独立的页表结构。进程间的内存是严格硬件隔离的，一个进程默认无法直接读取或修改另一个进程的内存。
- **线程**：属于同一个进程的多个线程**共享该进程的全部地址空间**（包括代码段、全局/静态数据段、堆内存）以及系统分配的资源（如文件描述符表）。
  - **线程私有部分极小**：仅包含**线程控制块（TCB）**、**程序计数器（PC）**、**通用寄存器上下文**以及**私有函数调用栈（Stack）**。

#### ② 调度开销与上下文切换（Context Switch）

- **进程切换（重量级）**：
  - 必须保存并恢复 CPU 寄存器上下文；
  - **必须切换页表基址寄存器（如 x86 的 CR3）**，这会导致 CPU 的**快表（TLB，Translation Lookaside Buffer）大面积失效/刷新**，引起随后的内存访问命中率骤降，切换代价高昂。
- **线程切换（轻量级）**：
  - 仅涉及同一进程内的线程切换时，**虚拟地址空间不变，页表不切换，TLB 无需刷新**。
  - 只需保存和切换少量的 CPU 寄存器和栈指针（SP），耗时通常比进程切换低一个数量级。

#### ③ 通信与协作机制

- **进程间通信（IPC）**：由于地址空间相互隔离，两个进程交换数据必须走内核管道（Pipe）、消息队列、共享内存（Shared Memory）或套接字（Socket），机制相对复杂。
- **线程间通信**：同一进程内的线程天然处于同一内存空间，直接读写全局变量或堆上的数据结构即可完成数据交互，极其高效；但也正因共享内存，多线程必须借助**互斥锁、信号量、条件变量**等机制防止数据竞态。

#### ④ 健壮性与容错能力

- **进程**：相互隔离。一个进程因为空指针解引用触发段错误（Segmentation Fault）崩溃退出，操作系统会直接回收其资源，一般不会直接导致系统内其他进程崩溃。
- **线程**：共享地址空间。进程内任何一个线程如果发生致命内存越界破坏了共享内存，或者收到终止信号，通常会直接导致**整个进程的所有线程一同覆灭**。

### 3. 核心对比表

| **对比维度**       | **进程（Process）**               | **线程（Thread）**               |
| ------------------ | --------------------------------- | -------------------------------- |
| **系统定位**       | **资源分配与保护**的基本单位      | **CPU 调度与分派**的基本单位     |
| **内存与地址空间** | 各自拥有独立的虚拟地址空间        | 同一进程内的线程共享整个地址空间 |
| **私有数据结构**   | PCB、完整页表、独立堆栈、文件表等 | TCB、PC、寄存器集合、独立函数栈  |
| **上下文切换代价** | **高**（需切换页表并刷新 TLB）    | **低**（仅切换寄存器与栈指针）   |
| **通信成本**       | 较高（需依赖内核 IPC 机制）       | 极低（直接读写共享内存变量）     |
| **相互影响**       | 独立隔离，互不干扰                | 共享风险，一个崩溃易导致全盘崩溃 |

## 用户级线程与内核级线程

用户级线程与内核级线程的根本区别，在于**由谁来感知、创建、调度和管理这些线程**：是用户空间的**线程库（运行时环境）**，还是操作系统的**内核（Kernel）**。

### 1. 用户级线程（User-Level Thread, ULT）

- **管理主体**：完全由用户空间的**线程库**（如早期的 Green Threads、GNU Portable Threads）进行管理。操作系统内核对它们的存在**一无所知**，在内核眼中，整个程序只是一个普通的单线程进程。
- **执行机制**：
  - 线程控制块（TCB）维护在进程自身的用户内存空间中。
  - 线程的创建、销毁、调度和上下文切换全部在用户态完成，**无需发生用户态到内核态的模式切换（Mode Switch）**。
- **主要优势**：
  - **开销极低、切换速度极快**：上下文切换仅需保存和恢复几个通用寄存器和栈指针，不需要执行昂贵的系统调用中断。
  - **灵活性高**：可以根据应用场景自行定制调度算法（如协程调度）。
- **核心缺陷**：
  - **一人阻塞，全盘阻塞**：由于内核只认识该进程，若进程内某个用户级线程发起了阻塞式系统调用（如读取磁盘文件未就绪），内核会把**整个进程**挂起，导致其他未阻塞的用户级线程也无法运行。
  - **无法利用多核 CPU 的并行能力**：内核以进程为单位进行调度，即便物理主机有 16 个 CPU 核心，内核同一时刻也只能将该进程调度到 1 个物理核心上执行，无法做到多线程真正的硬件级并行。

### 2. 内核级线程（Kernel-Level Thread, KLT）

- **管理主体**：直接由**操作系统内核**创建、调度与维护。现代主流桌面及服务器操作系统（如 Windows、Linux、macOS）的本地线程实现均为内核级线程。
- **执行机制**：
  - 内核空间中为每个线程维护独立的内核级 TCB。
  - 线程调度由内核的调度程序（Scheduler）统一掌控，CPU 时间片是直接分配给具体线程的。
- **主要优势**：
  - **支持真并发（多核并行）**：内核可以同时将同一个进程内的多个内核级线程分派到不同的物理 CPU 核心上并行计算。
  - **阻塞隔离**：若一个线程发起阻塞式 I/O，内核仅阻塞该线程，同一进程内的其他内核级线程仍可被调度继续执行。
- **主要缺陷**：
  - **切换开销相对较大**：同一进程内的线程切换时，虽然不需要刷新 TLB 和切换页表，但必须通过中断/系统调用**从用户态陷入力度较深的内核态**，保存与恢复内核寄存器状态。

### 3. 多线程模型（映射关系）

在操作系统架构中，用户空间看到的逻辑线程与内核调度的物理线程之间，存在三种映射模型：

1. **多对一模型（$M:1$）**：
   - 多个用户级线程映射到 1 个内核级线程（即纯粹的用户级线程实现）。
   - 优点是线程切换快，缺点是无法多核并行且容易单点阻塞。
2. **一对一模型（$1:1$）**：
   - 每个用户创建的线程都严格对应一个内核级线程。
   - **这是 Windows（包括你在任务管理器中看到的所有线程）和 Linux（NPTL）采用的标准模型**。并发性能好，调度完全由操作系统统筹。
3. **多对多模型（$M:N$，又称两级模型）**：
   - 将 $M$ 个用户级线程复用映射到 $N$ 个内核级线程上（$M \ge N$）。
   - 例如 **Go 语言的 Goroutine（GMP 模型）**，在用户态实现了轻量级协程调度，底层挂载在系统的内核级线程池上，兼顾了快速切换与多核并行能力。

### 对比总结

| **比较维度**     | **用户级线程 (ULT)**                  | **内核级线程 (KLT)**                   |
| ---------------- | ------------------------------------- | -------------------------------------- |
| **存在位置**     | 用户空间（线程库实现）                | 内核空间（操作系统原生支持）           |
| **内核是否感知** | **否**（内核只看到一个进程）          | **是**（内核直接调度线程）             |
| **切换开销**     | **极小**（纯用户态切换，无陷阱调用）  | **较小但高于 ULT**（需陷入内核态）     |
| **多核并行能力** | **不支持**（只能跑在单个 CPU 核心上） | **原生支持**（多核硬件真并行）         |
| **系统调用阻塞** | 一个线程阻塞，**整个进程全部挂起**    | 一个线程阻塞，**不影响其他线程执行**   |
| **典型代表**     | 各种协程库、早期 Java 绿线程          | Windows 线程、Linux 原生线程 (pthread) |
