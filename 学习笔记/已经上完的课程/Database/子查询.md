> **14. 下列哪种运算不能引出子查询（ A ）**
>
> A. LIKE

>

你在卷子上非常果断地勾选了 **A. LIKE**，这个直觉极其敏锐。但在 SQL 的学术世界和教务大题里，**子查询（Subquery）的引出方式和分类**是一套有着严密逻辑的体系。

为了让你在简答题或者接下来的 SQL 动笔大题里写得天衣无缝，我们今天把“如何用不同的谓词去引出子查询”这个核心考点做一次硬核的系统拆解。

## 🏗️ 核心底层：什么是 SQL 子查询？

子查询，说白了就是“嵌套在另一个 SQL 语句内部的 `SELECT` 查询语句”。它的本质是：**外层的主查询在执行时，需要内层的子查询先帮它算出一个“临时结果”，作为外层查询的过滤条件。**

在标准 SQL 的 `WHERE` 子句中，能够引出子查询的谓词（关键词）被严格分为四大门派。我们对照着选项逐一解剖：

## 🛡️ 门派一：集合成员谓词（引出多行子查询） —— 【对应 B 选项 IN】

这是考场上最常见、写 SQL 大题时天天都在用的语法。

- **学术语义**：当子查询返回的结果不是一个孤零零的数字，而是一整列、好几个值（一个集合）时，外层必须用 `IN`（或者 `NOT IN`）来衔接。

- **考场真题实战演练**：

  查询和“张三”在同一个系学习的所有学生的姓名。

  SQL

  ```sql
  SELECT SNAME FROM 学生表
  WHERE SDEPT IN (
      -- 这个子查询会查出张三所在的系（比如 '计算机系'）
      SELECT SDEPT FROM 学生表 WHERE SNAME = '张三'
  );
  ```

- **结论**：`IN` 是引出子查询的绝对主力，B 选项完全合法。

## 👁️ 门派二：存在量词谓词（引出相关子查询） —— 【对应 D 选项 EXISTS】

这是关系代数中“全称量词”在 SQL 里的唯一物理实现，也是大题的失分重灾区。

- **学术语义**：`EXISTS` 配合子查询时，**它根本不关心子查询具体查出了什么数据，它只关心子查询“能不能抓到人（结果集是否为空）”**。只要子查询能查出至少一行数据，`EXISTS` 就返回真（TRUE）。

- **考场真题实战演练**：

  查询选修了 'C1' 号课程的学生姓名。

  SQL

  ```sql
  SELECT SNAME FROM 学生表 S
  WHERE EXISTS (
      -- 拿着外面的学生学号，去流水账里对，对上了就说明该生选了
      SELECT * FROM 选课表 SC 
      WHERE SC.SNO = S.SNO AND SC.CNO = 'C1'
  );
  ```

- **结论**：`EXISTS` 后面必须死死跟随一个子查询，D 选项是天生的子查询谓词。

## 📏 门派三：比较/范围谓词（引出单值子查询） —— 【对应 C 选项 BETWEEN...AND】

这个选项极具欺骗性，很多同学第一眼看到它就会觉得它不能接子查询，这就中了出题人的调虎离山计。

- **学术语义**：`BETWEEN...AND...` 的本质是范围匹配。在标准 SQL 中，只要你的子查询**确保只返回一个孤零零的单值（比如用聚合函数 `AVG`、`MIN`、`MAX` 算出来的数字）**，它就可以完美地嵌套在 `BETWEEN` 和 `AND` 的后面。

- **考场真题实战演练**：

  我们要查询工资介于“全校最低工资”和“全校平均工资”之间的教职工信息。

  SQL

  ```
  SELECT * FROM 教师表
  WHERE 工资 BETWEEN 
      (SELECT MIN(工资) FROM 教师表) -- 子查询1：引出单值（如 4000）
      AND 
      (SELECT AVG(工资) FROM 教师表); -- 子查询2：引出单值（如 8000）
  ```

- **结论**：只要子查询给力、返回的是单值，`BETWEEN...AND...` 就能完美引出！C 选项安全通过安检。

## ❌ 终极死刑：为什么 LIKE 绝对无法引出子查询？

现在我们来看你揪出来的内鬼 —— **A. LIKE**。

- **LIKE 的铁血定义**：`LIKE` 在 SQL 里是专门用来做**字符串模糊匹配（Pattern Matching）\**的。它的右边，语法上\**死死地限定了必须是一个“字符串字面量模式”**。

- **它的日常形态**：`WHERE SNAME LIKE '张%'` 或者 `LIKE '_三%'`。

- **为什么不能接子查询**：

  如果你强行在后面写 `WHERE SNAME LIKE (SELECT ...)`，在编译阶段，DBMS 的语法解析器就会直接报错（Syntax Error）。因为 `LIKE` 在底层匹配时需要一个确定的字符串模糊模板（带有 `%` 或 `_` 通配符），它无法动态地去解析、匹配一个子查询返回的数据表、列甚至多行集合。

## 📌 考场秒杀大局观总结

过几天在考场上，不管是选择题还是写 SQL 填空，牢记这四句话：

1. 右边是**多行集合** ➡️ 用 **`IN`** 引导子查询。
2. 右边是**单值数字/日期** ➡️ 用 **`>`、`<`、`= ` 或者是 `BETWEEN...AND`** 引导子查询。
3. 只要判断**有没有人、存不存在** ➡️ 用 **`EXISTS`** 引导子查询。
4. 看到 **`LIKE`** ➡️ 老老实实写字符串和 **`%`**，它跟子查询生来八字不合，严禁混用！
