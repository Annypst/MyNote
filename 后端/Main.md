### 📘 Java Web 复习笔记：Tomcat 篇

#### 1. Tomcat 目录结构

- 📂 **`bin/`**：存放 Tomcat 的**可执行脚本命令**。
  - `startup.bat` (Windows) / `startup.sh` (Linux)：**启动** Tomcat 服务器。
  - `shutdown.bat` / `shutdown.sh`：**关闭** Tomcat 服务器。
- 📂 **`conf/`**：存放 Tomcat 的各种**配置文件**。
  - `server.xml`：核心配置文件，用于修改**端口号**、配置虚拟主机等。
  - `web.xml`：全局的 Web 应用配置文件。
- 📂 **`logs/`**：存放 Tomcat 运行时的**日志文件**，用于排查异常和诊断错误。
- 📂 **`webapps/`**：存放部署的 **Web 应用程序**（你的项目文件就放在这里）。

#### 2. 核心配置：修改端口号

- **默认端口**：`8080`。
- **修改路径**：`tomcat/conf/server.xml`。
- **修改方法**：找到 `<Connector port="8080" protocol="HTTP/1.1" ... />`，将 `port` 的值改为你需要的端口（例如 `8081`）。

### 📘 HTTP 协议基础

#### 1. HTTP 请求消息结构

- 1️⃣ **请求行**：包含 **请求方法**（如 GET/POST）、**资源路径（URI）**、**协议版本**。

  - *示例*：`GET /exam/index.jsp HTTP/1.1`

  - 

    *注意*：这里的斜杠 `/` 代表 Web 应用的**根路径**或特定的**虚拟目录** 。  

- 2️⃣ **请求头**：由多个键值对组成，用于通知服务器客户端的属性（如 `Accept`, `Host`） 。  

- 3️⃣ **空行**：一个完全空白的行（`\r\n`），用来**隔离**请求头与请求体。

- 4️⃣ **请求体**：POST 请求时才会有，存放具体提交的表单数据。

#### 2. HTTP 响应消息结构

- 1️⃣ **响应状态行**：包含协议版本、**状态码**、状态码描述 。  
- 2️⃣ **响应头**：服务器返回给浏览器的附加信息（如 `Content-Type`, `Location`） 。  
- 3️⃣ **空行**：**隔离**响应头与响应体 。  
- 4️⃣ **响应体**：服务器返回给浏览器的具体 HTML 页面、图片或 JSON 数据 。  

### 📘 HTTP 状态码

#### 3. 核心 HTTP 状态码分类

- **2xx 成功**：
  - `200 OK`：请求成功，服务器成功返回数据。
- **3xx 重定向/缓存**：
  - `302 Move Temporarily`：临时重定向（常用于登录后的页面跳转）。
  - `304 Not Modified`：资源未修改，使用浏览器本地缓存。
- **4xx 客户端错误**：
  - `404 Not Found`：资源不存在（通常是 URL 路径写错了）。
- **5xx 服务器错误**：
  - `500 Internal Server Error`：服务器内部错误（通常是 Java 后端代码抛出了异常）。

### 📘 HTTP 请求方式对比

#### 4. GET 与 POST 的核心区别

| **特性**     | **GET 方法**                                 | **POST 方法**                               |
| ------------ | -------------------------------------------- | ------------------------------------------- |
| **参数位置** | 拼接在 **URL（请求行）** 后面                | 存放在 **请求体（Body）** 中                |
| **可见性**   | 浏览器地址栏可见，容易被窥窃                 | 地址栏不可见，相对隐蔽                      |
| **数据大小** | 受 URL 长度限制（通常几 KB），不能传大盘数据 | 理论上**无限制**，适合**文件上传**          |
| **历史记录** | 会被浏览器主动缓存、保留历史记录             | 不会被缓存，不会保留历史记录                |
| **典型应用** | 数据的**查询**（如搜索、看帖）               | 数据的**提交/修改**（如登录、注册、传文件） |

### 📘 Servlet 生命周期

#### 1. Servlet 核心生命周期方法

- 🟢 **`init(ServletConfig config)`**：**初始化阶段**。Servlet 诞生时执行，**仅执行一次**。
- 🔵 **`service(HttpServletRequest req, HttpServletResponse resp)`**：**服务阶段**。每次请求都会执行。
  - *注意*：我们在开发中通常不直接重写 `service()`，而是重写其子类 `HttpServlet` 的 **`doGet()`** 和 **`doPost()`**。
- 🔴 **`destroy()`**：**销毁阶段**。服务器关闭或应用卸载时执行，释放资源，**仅执行一次**。

### 📘 Servlet 核心 API

2. request 与 response 的核心分工   

📥 HttpServletRequest 常用方法（获取数据）   

- 

  **`getParameter(String name)`**：获取浏览器提交的**表单参数**或 URL 中的参数 。  

- 

  **`getAttribute(String name)` / `setAttribute()`**：在 **Request 域**中读取/存入数据（常用于请求转发时传递数据） 。  

- 

  **`getSession()`**：获取或创建一个 **Session 对象** 。  

- 

  **`getCookies()`**：获取浏览器携带的所有 **Cookie** 。  

- 

  **`getRequestDispatcher(String path).forward(req, resp)`**：实现服务器内部的**请求转发** 。  

📤 HttpServletResponse 常用方法（发送数据）   

- 

  **`setContentType(String type)`**：设置响应的内容类型和**编码格式**（防止中文乱码） 。  

- 

  **`getWriter()`**：获取字符输出流（`PrintWriter`），用来向网页**打印/输出文本内容** 。  

- 

  **`addCookie(Cookie cookie)`**：向浏览器**发送/写入 Cookie** 。  

- **`sendRedirect(String location)`**：告诉浏览器进行**重定向**（页面跳转）。

### 📘转发与重定向对比

#### 3. 请求转发与重定向的区别

| **特性**       | **请求转发 (Forward)**                                      | **重定向 (Redirect)**                                   |
| -------------- | ----------------------------------------------------------- | ------------------------------------------------------- |
| **发生位置**   | **服务器内部**，Servlet 之间跳转                            | **浏览器端**，客户端重新发起请求                        |
| **请求次数**   | 只有 **1 次**请求                                           | 一共 **2 次**请求                                       |
| **地址栏变化** | **不变**（依旧保持第一次请求的 URL）                        | **改变**（变为最终重定向后的新 URL）                    |
| **数据共享**   | 可以通过 `request` 域共享数据                               | 无法通过 `request` 域共享（因为是新请求）               |
| **跳转范围**   | 只能跳转到**当前 Web 应用**内部的资源                       | 可以跳转到**任意外部网站**（如 `http://www.baidu.com`） |
| **核心代码**   | `request.getRequestDispatcher("/path").forward(req, resp);` | `response.sendRedirect("/path");`                       |

### 📘 会话技术基础

- 🍪 **Cookie（客户端技术）**：
  - **数据存在哪里**：数据以文本的形式保存在**浏览器（客户端）**。
  - **安全性**：因为保存在本地，用户看得见也改得着，所以**安全性较低**。
  - **应用场景**：适合保存不敏感的数据，比如“记住用户名”、“自动登录”。
- 📦 **Session（服务端技术）**：
  - **数据存在哪里**：数据保存在**服务器内存**中。
  - **安全性**：用户无法直接看到或修改服务器上的数据，所以**安全性更高**。
  - **应用场景**：适合保存核心敏感数据，比如“用户的登录状态”、“购物车的商品”。

### 📘 会话技术进阶

#### 1. Cookie 的生命周期 API

在课本 5.2.2 节和样题选择题第 12 题中，都考查了控制 Cookie 在浏览器保存时间的 API：`setMaxAge(int expiry)`。

- ⏳ `setMaxAge(正数)`：控制 Cookie 在浏览器硬盘上的**存活秒数**（比如 `60*60` 代表存活 1 小时）。
- ❌ `setMaxAge(0)`：通知浏览器**立即删除**这个 Cookie。
- 🌐 `setMaxAge(-1)`：默认值。代表该 Cookie 只在**当前浏览器窗口**存活，一旦关闭浏览器，Cookie 就会被自动删除。

#### 2. Session 的超时销毁

在课本 5.3.3 节和样题选择题第 19 题中，考查了 Session 的自动过期配置。

- 🛠️ **全局配置**：在 `web.xml` 中通过 `<session-timeout>` 标签配置。
- ⚠️ **核心单位**：注意！代码里的时间单位是**分钟**，而不是秒或毫秒。例如配置 `<session-timeout>2</session-timeout>`，代表用户如果连续 **2 分钟**没有操作，Session 就会自动销毁。

### 📘 JSP 与 EL/JSTL 标签

#### 1. JSP 的两种包含方式对比

| **特性**     | **静态包含 (<%@include file="..." %>)**                      | **动态包含 (<jsp:include page="..." />)**                |
| ------------ | ------------------------------------------------------------ | -------------------------------------------------------- |
| **语法**     | `<%@include file="Header.jsp" %>`                            | `<jsp:include page="Header.jsp" />`                      |
| **发生时间** | **编译时**包含。把两个文件的代码合并成一个 Servlet，再进行编译。 | **运行时**包含。两个文件分别编译，运行时把结果嵌入进来。 |
| **变量共享** | 两个页面可以**直接共享**同一个 Java 变量。                   | 两个页面变量独立，需要通过参数或域对象传递。             |

#### 2. EL 表达式（Expression Language）基础

- 🎯 **作用**：用来简化 JSP 页面中的 Java 代码，快速从四大域对象中**获取数据**。
- ✍️ **语法**：`${表达式}`
- 🔍 **样题考查点**：
  - 运算：`${(1<2) ? 3 : 4}` 的结果是 `3`。
  - 获取数组/集合数据：`${users[0].name}` 代表获取 `users` 数组中第一个元素的 `name` 属性。

#### 3. JSTL 标签库（JSP Standard Tag Library）

- 🎯 **作用**：配合 EL 表达式，代替 JSP 中的 Java 逻辑判断（`if`）和循环（`for`）。
- 🛠️ **常用核心标签（Core）**：
  - `<c:if test="${条件}">`：条件判断。
  - `<c:forEach items="${集合}" var="遍历变量">`：循环遍历。

### 📘 MVC 模式与数据传递（从零开始）

在规范的 Java Web 开发中，各个组件的分工是这样的：

- 🎮 **Controller（控制器）—— 由 Servlet 担任**：
  - 负责接收用户的请求。
  - 调用后台资源（Model）获取数据。
  - 将数据存入 `request` 域中。
  - 通过请求转发（Forward）将请求和数据一起带给 JSP。
- 📺 **View（视图）—— 由 JSP 担任**：
  - **不负责**产生数据，只负责从域对象中**取出数据**并展示在网页上。

## 📂 第 8 章：JavaBean 技术与 MVC 开发模型

### 1. 什么是 JavaBean？

在 Java Web 中，JavaBean 其实就是一个**规范的 Java 类**，它专门用来**封装数据**（比如把用户的账号、密码、邮箱打包成一个对象整体移动）。

课本 8.1 节和样题选择题第 18 题明确规定，一个合格的 JavaBean **必须满足以下强制规范**：

1. 🔒 **属性私有化**：所有成员变量必须用 `private` 修饰。
2. 🔓 **公共访问方法**：必须为每个私有属性提供公共的 `getXXX()` 和 `setXXX()` 方法。
3. 👶 **必须有无参构造方法**：必须提供一个 `public` 的无参数构造函数（方便 Tomcat 自动通过反射创建它）。
