### 🎯 阵地一：HTTP 协议与状态码（绝对送分题）



**【五年考频】**：极高，每年试卷的前 5 题必有它的身影 。  

- **规律总结**：翻来覆去只考几个经典的数字和头字段。

- **核心射击点**：

  - **`500`** ➡️ 服务器内部错误（你的 Java 代码写挂了）。

  - **`404`** ➡️ 找不到资源（路径写错了）。

  - **`302`** ➡️ 重定向（配合 `Location` 头使用）。

  - 

    **`Refresh`** ➡️ 自动刷新页面，**单位是秒** 。  

- **⚠️ 扩展防背刺**：

  - 

    *变种题*：“哪个头字段用于通知客户端获取请求文档的新地址？” ➡️ 答案是 **`Location`**（它总是和 302 狼狈为奸） 。  

  - 

    *陷阱题*： Tomcat 的默认端口是 `8080`，但 HTTP 协议本身的默认端口是 **`80`**。看清题目问的是谁 。  

### 🎯 阵地二：JSP 与 Servlet 的恩怨情仇（代码执行底层）



**【五年考频】**：极高，判断题和选择题的重灾区 。  

- **规律总结**：极其喜欢考 `out` 对象和响应流的冲突，以及 MVC 的对应关系。

- **核心射击点**：

  - 

    **`out` 缓冲区别踩雷**：同页面中，`response.getWriter()` 永远比 `out.println()` **先输出**（即使代码写在后面） 。  

  - **生命周期调用次数**：`init()` 和 `destroy()` 一辈子只执行**1 次**；`service()`（或 doGet/doPost）每次请求都执行。

  - 

    **大总管 `ServletContext`**：它可以让整个 Web 应用的所有 Servlet 共享数据 。  

- **⚠️ 扩展防背刺**：

  - 

    *变种题*：选择题问 `out` 和 `response.getWriter()` 的真实返回类型。记住：`out` 是 **`JspWriter`**，`getWriter()` 是 **`PrintWriter`** 。  

  - 

    *陷阱题*：判断题如果说“`response.getOutputStream()` 和 `response.getWriter()` 可以同时使用”，**坚决打叉！** 字节流和字符流在同一次响应中互斥，强行一起用会报 `IllegalStateException` 。  

### 🎯 阵地三：JDBC 的父子局与游标走位



**【五年考频】**：年年必考，填空题也会出 。  

- **规律总结**：死磕 `Statement` 和 `PreparedStatement` 谁是爹谁是儿子，以及 `ResultSet` 的指针。

- **核心射击点**：

  - 

    **父子关系**：长的是儿子（`PreparedStatement`），短的是老子（`Statement`）。**只有儿子能预编译和使用 `?` 占位符防 SQL 注入** 。  

  - 

    **执行方法**：`executeQuery()` 专职 `SELECT` ；`executeUpdate()` 搞定增删改，返回受影响的行数（`int`） 。  

- **⚠️ 扩展防背刺**：

  - 

    *变种题*：`ResultSet` 游标除了考 `absolute(int row)` 定位指定行，还会考向上一行 **`previous()`** ，向下 **`next()`**，以及移动到最后一行 **`last()`** 。  

  - 

    *陷阱题*：判断题说“对同一条 SQL，`Statement` 会预编译并缓存”。**错！** `Statement` 是个憨憨，每次都重新编译，`PreparedStatement` 才会预编译 。  

### 🎯 阵地四：EL 表达式与隐式对象（最爱玩文字游戏）



**【五年考频】**：极高，坑点最密集的地方 。  

- **规律总结**：重点考察语法格式的正确性，以及 EL 隐式对象和 JSP 隐式对象的区分。

- **核心射击点**：

  - 

    **等效替代**：`request.getAttribute("p")` 等价于 **`${requestScope.p}`** 。  

  - 

    **数组/复数获取**：获取数组元素要用方括号 `${users[1].name}`（注意索引从 0 开始）；获取多选框值用带尾巴的 **`paramValues`** 。  

  - 

    **唯一交集**：EL 的 11 个隐式对象和 JSP 的 9 个隐式对象，**唯一的共同点是 `pageContext`**（常出判断题说它们毫不相关，必须打叉） 。  

- **⚠️ 扩展防背刺**：

  - 

    *变种题*：条件运算符（三元运算）。如 `${(1<2)?3:4}`，前面为真就输出冒号前面的 **3** 。  

  - 

    *陷阱题*：获取请求头字段的值，隐式对象是 **`header`**（很多人会手滑选 param） 。  

### 🎯 阵地五：动作标签、指令与 MVC 分工



**【五年考频】**：高频稳定 。  

- **规律总结**：死扣 MVC 谁负责干什么，以及 `<jsp:xxx>` 和 `<%@ xxx %>` 的匹配关系。

- **核心射击点**：

  - 

    **MVC 铁三角**：在 JSP Model2 中，**Controller（控制器）绝对是 Servlet**（负责接收请求），View 是 JSP，Model 是 JavaBean（负责业务数据和规则） 。  

  - 

    **包含语法死绑**：带冒号的动作标签必配 `page`（`<jsp:include page="..." />`）；带百分号的指令必配 `file`（`<%@ include file="..." %>`） 。  

  - 

    **`page` 指令**：设置文档类型用 `contentType` ；唯一可以重复出现的属性是 `import` 。
