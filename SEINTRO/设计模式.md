下面这张分类图展示了它们的总体结构。我们按照**创建型（5种）**、结构型（7种）**和**行为型（11种）的顺序，用“一句话核心 + 大白话场景”的极简方式，带你把 23 种全部过一遍。



## 一、 创建型模式（Creational）—— 解决“对象的创建”问题（5种）

这组模式的目的都是为了**把对象的创建和使用解耦**，别让满屏幕都是 `new`。

| **模式名称**                       | **一句话核心目标**                                           | **大白话生活场景**                                           |
| ---------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **1. 单例 (Singleton)**            | 保证一个类在全局永远只有一个实例。                           | 系统的线程池、全局配置管理器、一个国家的总统。               |
| **2. 工厂方法 (Factory Method)**   | 定义一个创建对象的接口，让子类决定实例化哪一个具体类。       | 麦当劳分店。你想要汉堡，分店（子类工厂）负责制作并交给你，总店只定标准。 |
| **3. 抽象工厂 (Abstract Factory)** | 创建一系列相关或相互依赖对象的家族，而无需指定它们具体的类。 | 电子厂（比如富士康）。不仅能组装苹果手机，还能组装苹果配套的充电器和耳机。 |
| **4. 建造者 (Builder)**            | 将一个复杂对象的构建与其表示分离，使得同样的构建过程可以创建不同的表示。 | 组装DIY电脑或点赛百味三明治。你需要一步步选择面包、肉类、蔬菜，最后拼出一个复杂的三明治。 |
| **5. 原型 (Prototype)**            | 通过复制（克隆）现有的实例来创建新的对象，而不是通过 `new`。 | 细胞分裂、火影忍者里的影分身，或者直接在代码里做 `clone()` 深拷贝。 |

## 二、 结构型模式（Structural）—— 解决“类和对象的组合”问题（7种）

这组模式就像“乐高积木的连接件”，用来**理清类与类之间的关系**，让它们组合得更灵活。

| **模式名称**              | **一句话核心目标**                                           | **大白话生活场景**                                           |
| ------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **6. 适配器 (Adapter)**   | 将一个类的接口转换成客户希望的另一个接口，让接口不兼容的类可以一起工作。 | 手机充电转接头、出国旅游用的电源插头转换器。                 |
| **7. 桥接 (Bridge)**      | 将抽象部分与它的实现部分分离，使它们都可以独立地变化。       | 毛笔与蜡笔的区别。如果要画 3 种大小、5 种颜色的线条，蜡笔需要 15 支；毛笔只需要 3 支（大小）+ 5 盒颜料（颜色），通过组合（桥接）来实现。 |
| **8. 组合 (Composite)**   | 将对象组合成树形结构以表示“部分-整体”的层次结构，使得用户对单个对象和组合对象的使用具有一致性。 | 电脑的文件系统（文件夹里既可以有文件，也可以有子文件夹）。   |
| **9. 装饰器 (Decorator)** | 动态地给一个对象添加一些额外的职责。完全替代继承。           | 给奶茶加珍珠、加椰果。奶茶本质没变，但多加了料和价格。       |
| **10. 外观 (Facade)**     | 为子系统中的一组接口提供一个一致的界面，隐藏内部的复杂性。   | 前台接待或一站式政务大厅。你只需要对接一个人，他帮你去跑后台的各个部门。 |
| **11. 享元 (Flyweight)**  | 运用共享技术有效地支持大量细粒度的对象，减少内存消耗。       | 围棋游戏。棋盘上有上百个棋子，但其实只需要两个对象实例：一个“黑子原型”，一个“白子原型”，它们共享属性，只改变坐标。 |
| **12. 代理 (Proxy)**      | 为其他对象提供一种代理以控制对这个对象的访问。               | 经纪人、房产中介、明星的助理。粉丝（客户端）见不到明星本人，一切由助理（代理）传达。 |

## 三、 行为型模式（Behavioral）—— 解决“对象之间的通信和职责分配”（11种）

这组模式关注的是**对象怎么跑起来**，彼此之间如何打交道、传消息。

| **模式名称**                             | **一句话核心目标**                                           | **大白话生活场景**                                           |
| ---------------------------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **13. 职责链 (Chain of Responsibility)** | 让多个对象都有机会处理请求，将这些对象连成一条链，请求沿着链传递。 | 公司请假审批流。3天内主管批，7天内总监批，15天内CEO批。请求沿着管理链条往上传。 |
| **14. 命令 (Command)**                   | 将一个请求封装为一个对象，从而使你可用不同的请求对客户进行参数化。 | 饭店里顾客下的“订单”。服务员把你的需求写成一张纸条（命令对象），传给后厨，后厨什么时候做、谁来做都跟服务员解耦了。 |
| **15. 解释器 (Interpreter)**             | 给定一个语言，定义它的文法的一种表示，并定义一个解释器。     | 乱码翻译器、SQL解析器、计算器解析 `(1+2)*3`。                |
| **16. 迭代器 (Iterator)**                | 提供一种方法顺序访问一个聚合对象中的各个元素，而不需要暴露该对象的内部表示。 | 遥控器切台。你不需要知道电视机内部是怎么存储频道的，你只需要按“下一台”。 |
| **17. 中介者 (Mediator)**                | 用一个中介对象来封装一系列的对象交互，使各对象不需要显式地相互引用。 | 机场的塔台（调度中心）。所有的飞机不直接通信，全部和塔台通信，由塔台协调降落。 |
| **18. 备忘录 (Memento)**                 | 在不破坏封装性的前提下，捕获一个对象的内部状态，并在该对象之外保存这个状态，以便以后恢复。 | 游戏的“存档”功能、Word 里的 `Ctrl + Z` 撤销快捷键。          |
| **19. 观察者 (Observer)**                | 定义对象间的一种一对多的依赖关系，当一个对象的状态发生改变时，所有依赖于它的对象都会得到通知。 | 订阅B站UP主、微信群发消息。                                  |
| **20. 状态 (State)**                     | 允许一个对象在其内部状态改变时改变它的行为。对象看起来似乎修改了它的类。 | 自动售货机。当“有币”状态和“无币”状态下，按下投币按钮的反应完全不同。 |
| **21. 策略 (Strategy)**                  | 定义一系列的算法，把它们一个个封装起来，并且使它们可相互替换。 | 诸葛亮的锦囊妙计。去不同的地方、面对不同的敌人，掏出不同的锦囊（算法）来用。 |
| **22. 模板方法 (Template Method)**       | 定义一个操作中的算法的骨架，而将一些步骤延迟到子类中。       | 试卷模板。题目都是一样的（骨架），但每个人写的答案不同（子类具体实现）。 |
| **23. 访问者 (Visitor)**                 | 封装一些作用于某种数据结构中的各元素的操作，它可以在不改变数据结构的前提下定义作用于这些元素的新操作。 | 医院的处方单。划价员拿去算钱，药剂师拿去抓药。处方单（数据结构）不变，不同的人（访问者）对它执行不同的操作。 |
